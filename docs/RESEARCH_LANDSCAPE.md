## 3. Per-host interception mechanism — the architectural question

**Verdict up front: llm-router's own HOST_SUPPORT_MATRIX.md claim (hooks work on Claude Code / Gemini CLI / Pi; MCP-tool-only, best-effort elsewhere) is still substantially accurate in August 2026, even though every host's hook surface has grown since the doc's claims were probably written.** The critical distinction the doc gets right: growth in "hooks" on other hosts is about intercepting *tool calls*, not the *model/LLM API call itself* — so none of the newer hook systems let llm-router force a different model to answer a turn.

| **Codex CLI (OpenAI)** | Official docs at [developers.openai.com/codex/hooks](https://developers.openai.com/codex/hooks) (redirects to `learn.chatgpt.com/docs/hooks`). Confirmed.** |

### Bottom-line answer to the architectural question

Across Codex, Cursor, Windsurf, Claude Desktop (consumer app), and Copilot, **not one exposes a mechanism in 2026 that lets a third party deterministically decide which model answers a given native agent turn.** The available primitives are exactly the two the task hypothesized:
1. A static OpenAI-/Anthropic-compatible **base-URL + API-key override** (Cursor, Windsurf, Copilot BYOK) — same model for every call until a human reconfigures it, not per-prompt routing.
2. **Voluntary MCP tool calls** the host model chooses to invoke (all hosts) — "best-effort, not guaranteed," exactly as llm-router's own rules docs already say.

Every host's 2026 hook expansion (Codex, Cursor especially) adds interception of **tool calls, file access, and prompt submission** — useful for *blocking or logging*, not for *routing the model choice itself*. Claude Code and (per the existing doc, not independently re-verified in this pass) Gemini CLI/Pi remain structurally different because their hook fires *before the model sees the prompt* and can act on the host's own model-selection state (e.g., rewriting `~/.claude/settings.json` or programmatically switching `/model`) — a capability nobody else exposes.

**Strategic implication (evidence only, not my call to make):** the claim "auto-routing works on Claude Code / Gemini CLI / Pi, MCP-only elsewhere" is not just still true — it is *more* defensible in 2026 than a naive reading of "Codex and Cursor got hooks now!" would suggest, because none of those new hooks touch model selection. The multi-host "auto-routing" claim is only at risk if it's being read as "hooks work the same everywhere," which it currently is not.
