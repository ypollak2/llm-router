# Retention of router-owned history files

Companion to the B-02 notes (`docs/bugs/CTX-COMPACT-1.md`, `docs/bugs/CTX-PROJ-1.md`: session
copies do not outlive their TTL). This file lists the history files that have a retention rule.

## `quota_history.jsonl` (F107)

| Item | Value |
|---|---|
| Rows | `ts`, `five_hour_pct`, `weekly_pct`, `updated_at`, `five_hour_resets_at`, `source`. Quota percentages only, no prompt content. |
| Writers | `statusline_tick.maybe_append_history`, one row per 5-minute slot, also called from the default-layout refresher (`statusline_segments.append_history`). About 288 rows a day. |
| Kept | Rows with `ts` newer than 30 days (`statusline_tick.HISTORY_RETAIN_S`), and at most 20,000 rows (`HISTORY_MAX_ROWS`), newest first. |
| Why 30 days | Longest reader window is 14 days (`quota_rate.median_pp_per_active_hour`, `statusline_snapshot.BURN_DAYS`). 30 days adds a margin for `llm-router kpi --quota-burn --since/--until`, whose coverage block reads the same file for an absolute window; a window older than 30 days reports no history rows. |
| Prune | `statusline_tick.prune_history`: atomic rewrite (temp file, fsync, `os.replace`) under the writers' slot lock, at most once a day (mtime of `.quota_history.pruned`), run only by the background refresher (`statusline_segments.append_history`, `statusline_snapshot.refresh`), never by the synchronous status-line tick. Lines that are not JSON objects with a numeric `ts` are dropped by the rewrite. |
| Failure | A failed prune is recorded with `failopen` code `F107-HISTORY-PRUNE`; the file is left as it was. |
| Reads | `quota_rate` reads only the tail of the file it needs (backward scan in 256 KiB blocks). |

## `active_days.jsonl` (P3.7, S7, D-26 option A)

| Item | Value |
|---|---|
| Rows | `day` (local calendar date, `YYYY-MM-DD`) and `install_id` (16 random hex characters generated locally on the first row). Nothing else: no prompt text, no session id, no path. Nothing is sent anywhere. |
| Writer | `active_days.mark_active`, called from `quota_samples.append_session_sample` (the session-start background child and the Stop sample). Per session: one `stat` of the file (a file whose mtime is today already holds today's row, so no read); the tail read and the append happen at most once per day. Concurrent first writers share one install id (`active_days.id`, created with `O_EXCL`) and same-day duplicate rows are collapsed by the trim. Files are forced to mode 0600 on every write, not only on create. |
| Kept | One row per day, at most 400 rows (`active_days.MAX_ROWS`, about 13 months). Past that the file is rewritten atomically (temp file, fsync, `os.replace`), keeping the FIRST row (the install day and id) and the newest 399. The trim runs when the file is larger than 400 full rows (53 bytes each, `active_days._ROW_BYTES`). |
| Install day | The first marker day, not the operating-system install time: no earlier dated record exists. |
| Reads | `llm-router kpi --retention` and the last line of `llm-router kpi --quota-burn`: install day, active days, day 14, and "active on day 14" as yes / no / not yet (n/a before the first marker). Strict reading: "yes" needs a row dated exactly day 14; "not yet" holds while today is on or before day 14; active on day 15 but not day 14 is "no". The population rate (S7 70% across users) is LATER (16.1). |
| Failure | A failed write is recorded with `failopen` code `P37-ACTIVE-DAY`; the session start is never blocked. |
| Delete | Removing the file resets the install day and id. |

## `examples.jsonl` (P3.6-a, R-CLS-5, R-RTE-7; B-02 applies)

| Item | Value |
|---|---|
| Rows | `text_sha` (16 hex chars of the normalised prompt, `prompt_key`), `source` (`prefix`, `redo`, `rule`), `label` (0 or 1: does the prompt need a frontier model), `ts`. Forced-prefix rows keep their original `forced`, `decided`, `door` fields. **Prompt text is never stored.** |
| User-derived embeddings | A forced-prefix row written by the proxy or MCP may also hold `vec` (L2-normalised float32, base64) and `model`: **an embedding of the person's own prompt**, written only when `LLM_ROUTER_COMPLEXITY_KNN` is on and a kNN artifact exists. It is not the shipped corpus, and an embedding is partly invertible, so treat it as derived from the prompt. It is computed in a worker thread, never on the event loop. The hook writes the row hash-only (no network call on its path), so a hook-door row cannot join the index. |
| Hash only | A `redo` row (a human `r` press: only the proxy ledger's `text_sha` is left) and a `rule` row (an "always local" rule sentence: not a prompt, and an embedding of it would pollute the kNN neighbourhood) never carry `vec`. They are evidence, not index material. |
| Writers | `prefixes.record_example` (hook, proxy, MCP: a forced `local:`/`claude:`/... prefix), `receipt_band` signal `redone` through `examples.record_redo` (a `k` press is not recorded, it is not a test), `user_rules.add_rules` for a `local_only` rule. Files 0600, directory 0700. |
| Kept | Rows newer than 180 days (`examples.MAX_AGE_S`). Older rows are **deleted from the file** on the next append and on every `llm-router learn` (readers also ignore them). At most about 2 MiB (`examples.MAX_BYTES`): past that the oldest half is dropped on the next append. |
| Reader | `llm-router learn` (`classifier_learning.apply`). Accepted examples that carry a `vec` are **copied into `complexity_knn.json`** (embeddings and 0/1 labels; the applied `text_sha` list, at most 5,000, and `examples_added_total` sit in its provenance so a row is applied once). The artifact has no TTL, and deleting `examples.jsonl` does not remove what an accepted update already put there. |
| Remove | `llm-router learn --purge-user-examples` rebuilds the artifact without the last `examples_added_total` rows (the ones `learn` appended; `build_complexity_knn.py` writes a fresh artifact with no `learning` provenance, so the tail rule holds) and then replaces `complexity_knn.json.prev` with a copy of the purged artifact (the pre-purge `.prev` held every user-derived embedding, so it is not kept; if it cannot be rewritten it is deleted, and the command reports a failure if it cannot be deleted). Then delete `examples.jsonl` (else the next `learn` applies those rows again). `rm ~/.llm-router/complexity_knn.json*` and rebuilding from the shipped corpus also works. |
| Failure | A failed write is recorded with `failopen` code `LR-FO-EXAMPLE` (or `LR-FO-PREFIX-EXAMPLE` for a prefix row); routing is never blocked. Prune and trim rewrites and every append hold `examples.jsonl.lock` (5 s bound for learn, prune and deferred writes; 0.25 s for the hook and the proxy/MCP inline write; past it the write is dropped and recorded), so a rewrite cannot drop a concurrent append. At most 32 deferred embeds are queued; a further one is dropped with `failopen` code `LR-FO-EXAMPLE-QUEUE`. |
| Concurrency | `llm-router learn` takes an exclusive lock (`complexity_knn.json.lock`) for the whole run (a second run waits up to 60 s, then exits 2 with a message; on Windows the lock is `msvcrt.locking`), writes through a unique temp file, and writes `.prev` only for a base artifact that is still the one it read. |

## `classifier_agreement.jsonl`, `classifier_learning.jsonl` and `classifier_conservative.json` (P3.6)

| Item | Value |
|---|---|
| `classifier_agreement.jsonl` | D-255. One row per turn on which the rules AND the L3 kNN both answered (`proxy/tiers.with_complexity_knn`, only when the kNN runs): `ts`, `rules_tier` (the rules' complexity), `knn_tier` (`frontier` or `standard`), `source`. No text, no hash, no embedding. Two generations of 1 MiB (`capped_log`, about 24,000 rows), so older rows go first; a heavy user's 28-day baseline may then be shorter than 28 days. |
| What it measures | Rules-vs-kNN **agreement** on the frontier boundary, not ground-truth accuracy. With the kNN off, no rows are written and `status` says "not measured (kNN off, n=0)". |
| Fallback | `classifier_shadow.jsonl` (the killed LLM classifier, D-121) is read only when there are no agreement rows and that file exists; the line is then labelled "LLM-shadow fallback". |
| `classifier_learning.jsonl` | One row per `llm-router learn` run: `ts`, `status`, `reason`, number of examples, and the replay `n`, exact-match and under-route of the current and candidate index. No text, no hashes. Two generations of 256 KiB (`capped_log`). |
| `classifier_conservative.json` | The conservative-mode switch: `active`, `checked_at`, `since`, `drop_pts`, window sizes. Written by the status and `kpi` checks; ignored once `checked_at` is 7 days old. |
| Replay set | Named by `LLM_ROUTER_LEARNING_REPLAY`; owned by the person, never copied or logged by the router. Every row needs a `text_sha` (the held-out guard); a file with a row that lacks one is rejected whole. |

## `local_check/runs/`, `attempts.jsonl` and `text_job_local` records (LC-7, D-259, design section 5)

| Item | Value |
|---|---|
| What | `llm-router local-check` measures the user's own local model on the shipped, public bank. Nothing here is user prompt text: the items are public commit and PR diffs from the bank. The model's **answers** to those items are the only generated text kept. No telemetry; nothing is sent anywhere by these files. |
| Run directory | `~/.llm-router/local_check/runs/<run_id>/` (directory 0700): `results.jsonl` (one line per item: status, timings, the model's answer in `text`), `judge.jsonl` (verdict, defect label, served judge model, cost), `meta.json`, `g3b.json` (plants gate). Files 0600. |
| Kept | The newest 3 run directories (`local_check.retention.KEEP_RUNS`), by the newest file mtime in the directory. A run that is an unexpired `open` reservation in `attempts.jsonl` (7 days, `attempts.RESERVATION_TTL_S`) is also kept, because the next run of that configuration must resume it. Older runs are deleted. A symlinked entry is skipped, never followed. |
| Answers | Once a kept run's `results.jsonl` is older than 30 days (`retention.ANSWER_DAYS`), the `text` of every record is blanked and `answer_pruned: true` is set; counts, statuses and timings stay. Atomic rewrite, 0600, mtime preserved. |
| Prune runs | `retention.prune()`, called by `llm-router doctor` (and available to the CLI after a run). It does not raise on unreadable or non-UTF-8 files or I/O errors; these are reported in `PruneReport.errors`, and an unreadable `attempts.jsonl` keeps every run (a failed delete can leave a run partly removed). A machine on which neither is run keeps its files until it is. |
| `attempts.jsonl` | `local_check/runs/attempts.jsonl` (0600): one line per attempt with configuration key, draw, verdict, per-item ok flags and counts. **No prompt or answer text.** It is the anti-retry log (draws used, 24 h cooldown, reservations), so it is not pruned; deleting it resets those limits for every model. |
| `text_job_local` records | In `local_eligibility.json` under `<model>.text_job_local.<job>`: grade, k, n, bank version and sha256, model digest, runtime, judge backend and served model, run id, date, scope, settings hash. No text. The latest scored result for a job replaces the previous one; a stale record (model digest changed, or 30 days with no digest) stays on disk for history and reads as unknown. Delete the `text_job_local` key to forget a model. |
| Nudge state | `local_check/nudge.json` (0600): the bank versions for which the one-line first-run tip was shown. Deleting it shows the tip again. |
| Reads | `llm-router status`, `doctor` and the fast status line read `local_eligibility.json` and the discovery cache only. They make no HTTP call and run no model. |

## `redo_validation/<run_id>/` (P3.6-c)

| Item | Value |
|---|---|
| `manifest.jsonl` | Sampled pair and session hashes, turn index, UTC day, stratum, detector signals/version, kind/source, previous served class, stratum counts and `exclusion_list_sha256`. Session ids are hashed; no prompt or answer text. |
| `frozen.json` | Counts, window, seed, run id, detector/manifest SHA256, strata, weights, threshold decision, concentration and shortfall. Records `exclusion_list_size`, `exclusion_list_sha256` and `allow_empty_exclusion`. Stores the salt so the local labeller can re-derive pair identities from transcripts. With `--include-untagged`, untagged sessions are first resolved through the proxy ledger's session stamps (the whole ledger is streamed; only session-to-kind stamps are held, so memory is bounded by streaming, not by time); a session with conflicting stamps is excluded and counted in `ledger_conflict_excluded` (also top-level); `counts` records `proxy_ledger` (present / missing; a missing ledger prints a warning; unreadable refuses the run), `proxy_ledger_rows`, `backfill_sidecar` (present / missing / unreadable / corrupt) and `untagged_causes` (tag, ledger and sidecar facets, counts only). Without the flag none of these keys are written. Stratum weights are `weights_combined` (organic and untagged together). No prompt or answer text or session ids. |
| `labels.jsonl` | Default owner/judge JSONL input: pair hash, categorical label (`redo`, `not_redo`, `unclear`, `lost`) and source only. Supplied by the local labeller; no transcript text. Repeated `--labels PATH` inputs are read in place, never copied. Keep local labels private (0600). |
| `test.used` | UTC timestamp line only. Created exclusively at 0600 before writing results; consumes the frozen run even if the subsequent result write fails. |
| `result.json` | Counts, label-source agreement, Wilson precision, weighted recall, seeded session-cluster bootstrap 95% intervals for precision and recall, sensitivity, validity warnings, completeness rule, gate verdict and frozen provenance. Bootstrap intervals are reporting only and never gate. No pair/session identities or transcript text. Unclear/lost labels are dropped from base recall denominators under a within-stratum missing-at-random assumption; concentrated draws have no recall estimate. |
| Completeness | Every flagged-stratum (F) pair must be labelled: any lost F pair voids the run. Overall lost above 5% also voids. Void takes precedence over sensitivity-based inconclusive outcomes. The rule is recorded in `completeness_rule`. |
| Sensitivity | Unclear labels are separately treated as redo and not_redo; `lost_as_not_redo` treats lost F labels as not_redo, including in recall, leaving S/R lost labels missing. Any gate flip against the base makes the outcome inconclusive unless void. |
| Validity | Reports unclear numerator, labelled denominator (excluding lost), and rate for F and overall. Either rate above 10% adds a printed warning; an empty denominator gives a null rate and no warning. |
| Writer | `llm-router redo-sample --freeze` writes manifest/frozen files; `llm-router redo-score` writes `test.used` then `result.json`, exclusively at 0600. `--census` and `--dry-score` write nothing. Dry scoring prints only labelled/unclear/lost counts per stratum, manifest/detector SHA check outcomes and agreement n; it refuses if either single-use output exists. A marker without results is spent and cannot be re-scored. |
| Local `redo_m09_excluded.txt` | State directory, or `--exclusion-file PATH`. Created by the owner, not by this command; recommended mode 0600, and census/freeze print a warning (no path) when it is group- or world-readable. Format: one unsalted pair-hash per line, with `#` comments. Hashes only, never shipped. Read-only by census/freeze; effective exclusion size, SHA256 and source (`local-file` or `shipped`) are reported. Every line that is not blank or a `#` comment must be 16 lowercase hex characters; otherwise census/freeze refuse with exit 2, naming the file `local` or `shipped` (never its path), and the invalid-line count only (the shipped file is checked the same way). A UTF-8 byte-order mark on the first line is ignored. |
| Permissions | Run directory 0700; files 0600. The `redo_validation` parent is set to 0700 only when created by this command. |
| Kept | Until superseded by a later validation; no automatic deletion. |
| Remove | On owner request, `rm -r` the run directory. |
| `labels_judge.jsonl`, `labels_owner.jsonl` | Written only by `llm-router redo-label --judge` / `--owner` (0600, append-only, fsynced per row). Each row is `{"pair_id","label","source"}` with label `redo`, `not_redo`, `unclear` or `lost`; nothing else. A pair whose transcript or turn is gone is written as `lost`, never `not_redo`. Pass them to `redo-score --labels`. Prompt and answer text is re-derived from the transcript at label time, held in memory only, and never written to a file, log or failopen record. |
| `judge_meta.json` | Written once by `redo-label --judge` (0600, exclusive create): `{"model_id", "allow_api_key"}`. The `--model-id` is required (no default) and must match on every resume. No text. |
| `judge_spend.json` | Written by `redo-label --judge` (0600, atomic replace, counts only): `{"calls", "usd", "rejected_streak", "estimated_calls"}`. `--max-calls` / `--max-usd` are cumulative against it and checked before each call against spend plus the call's $0.50 estimate (pre-charged, then replaced by the real cost); a corrupt or invalid file is refused (exit 2), never reset; two consecutive rejected batches need `--force-streak`; quota pauses (including unknown/stale quota) need `--force-quota`. Unknown costs are charged $0.50 and counted in `estimated_calls`. |
| `owner_sample.json` | Written by `redo-label --owner` (0600): the seed and the pair ids of the random non-flagged owner sample (all F pairs are always included). Ids only. |
| Judge runner | `redo-label --judge` runs `claude -p` with `--no-session-persistence` in an empty temporary working directory with an allow-listed environment and no `ANTHROPIC_BASE_URL`. The text leaves the machine only to the provider that already serves the sessions; the temporary directory is removed after each call. The spend cap (`--max-calls`, `--max-usd`) is cumulative per run via `judge_spend.json`. One redo-label process per run directory is enforced by an exclusive lock on `<run>/.lock` (0600, empty; a second process is refused with exit 2). |
| M0.9 exclusions | The shipped `src/llm_router/data/redo_m09_excluded.txt` stays empty. Local exclusions are unioned with the shipped list. Freeze refuses an empty effective list unless `--allow-empty-exclusion` is supplied. The size and SHA256 of sorted keys joined with newlines identify the effective list; its SHA256 is also included in every manifest row. |
| Tune dirs `redo_validation/tune-<id>/` | Written by `llm-router redo-sample --tune` (dir 0700, files 0600): the same `manifest.jsonl` and `frozen.json` as a test run, with `frozen.json` `purpose: "tune"`, `detector_variant: "v2"`, its own seed (361 by default) and the counts of excluded prior pairs. No supply gate. Disjoint by construction: the draw excludes the M0.9 list, every pair in any other run directory's manifest (test or tune, recomputed with each run's salt) and refuses (exit 2) when a sibling run directory cannot be read. A later `redo-sample --freeze` excludes every tune manifest's pairs and records `purpose: "test"`, `detector_variant`, `excluded_tune_pairs`, `n_tune_manifests`. One P3.6-c study has ONE canonical tune set: `--tune` refuses (exit 2) while a live tune run exists. `redo-sample --void-tune --run <id> --reason TEXT` voids one: it writes `voided.json` (`run`, `reason`, `voided_utc`; 0600, exclusive create; the reason is limited to 1-200 letters, digits, spaces and `.,:;()/#_-`, a procedure note, never prompt text) and keeps the directory, so its pairs stay excluded from later draws; every later `frozen.json` records `voided_tune_runs` and `n_voided_tune_runs`. A voided run cannot be tune-scored. Every `frozen.json` also records `projects_dir_sha256` (sha256 of the projects dir's real path, never the path), `projects_dir_default`, `allow_nondefault_projects_dir` and `projects_dir_transcripts` (count). The tune pool must be drawn from the census population, i.e. the default projects dir: `--tune` refuses another `--projects-dir` unless `--allow-nondefault-projects-dir` is passed, and that flag is recorded; drawing a tune pool from a curated directory is a procedure violation. Label it with `redo-label --run tune-<id>` unchanged. No `test.used` or `result.json` is ever written for a tune dir (`redo-score --tune` refuses a `purpose: test` run, and plain `redo-score` refuses a tune run). Kept until superseded; remove with `rm -r`. |
| `redo_validation/tune_log.jsonl` | Written by `redo-score --tune` (0600, append-only, fsynced): one counts-only row per scored candidate (`ts`, `tune_run`, `candidate`, `n_scored`, `n_unclear`, `n_lost`, overall and per-signal tp/fp/fn/precision/recall/f1, unweighted and stratum-weighted). No pair ids, no text. At most 2 distinct non-baseline `(candidate, detector_sha256)` pairs are ever accepted (M0.9 rule); a third pair refuses (exit 2). A run with 0 scored pairs logs nothing. Kept until superseded; removing it resets the widening count, so do not delete it between candidates. |
| Candidate detectors | `v3a` (tighten `repeat`: at least 12 words, Jaccard >= 0.9) and `v3b` (demote `repeat`: reported only with `reask` or `contradiction`) plus the recall-raising `v3c` (additional phrases rejecting the previous answer) and `v3d` (`v3c` plus short rejections of at most 6 words) in `redo_signal.VARIANTS`; `v2` stays the default. The owner must pick at most two non-baseline candidates from the union of all four for a tune log. Recomputed in memory from transcripts at score time; nothing about them is stored beyond the log counts. |
| Tune-log provenance | Each `tune_log.jsonl` row also stores `detector_sha256` (sha256 of `redo_signal.py` at scoring time), `tune_manifest_sha256` (the tune run's manifest sha256), `labels_sha256` (sha256 over the sorted sha256 hex digests of the label files read, one per line; bytes only, no path), `scored_pairs_sha256` (sha256 over the sorted pair ids actually scored, one per line), `projects_dir_sha256` and `projects_dir_default` (the transcript tree read), `n_manifest` and `variant_params` (`variant`, `description`). Each row also stores `label_names` (basenames of the label files read) and `owner_done` (true only when `owner_done.json` was valid, `labels_owner.jsonl` was among the files read and all files came from the run dir). `redo-label --owner` writes `owner_done.json` (0600; `n_labelled`, `labels_owner_sha256`, `others`, `owner_sample_sha256`; counts and digests, no pair id) only when every sampled pair is labelled AND the owner sample holds at least 20 S/R spot checks (`others`; design section 3 step 2: every F pair "plus 20 random S/R pairs"; `--others 0` or `1` completes no pass). It is an explicit marker because the owner may agree with the judge on every pair. Any later owner label makes it stale, and so does a changed owner sample: `owner_sample_sha256` is the sha256 over the sorted ids of the sample (every F pair plus the `owner_sample.json` spot checks, one per line), so after a larger `--others` the old marker is invalid until the extended sample is labelled and a new marker is written. A marker with `others` below 20 is invalid. Once the run has a canonical tune scoring (a log row with `owner_done` true and `n_lost` 0), `redo-label --owner` refuses (exit 2) to change the owner sample ("owner sample is fixed once a canonical tune scoring exists; void the run to change it"); raise `--others` before the first canonical scoring. Migration: a marker written by PR #712 (no `others`, no `owner_sample_sha256`) now reads invalid; one `redo-label --owner` rerun with nothing left to label rewrites a valid marker (labels are untouched), after which a re-score is canonical. If the manifest holds fewer than 20 S/R pairs the owner pass can never complete (the command prints the available count); there is no supply gate at draw time. Hand-editing `owner_sample.json` is a procedure violation like editing a label file. A scoring made before that pass is complete still prints F1 and is logged with `owner_done: false`, but is non-canonical: it locks nothing and cannot be frozen (PR3d; the judge file alone labels every pair and used to lock the run before the owner wrote a label). The labels digest of the first complete row (n_lost 0) with `owner_done` true on a tune run is that run's canonical labels source: a later `redo-score --tune` on that run with other label files refuses (exit 2, "labels changed for this tune run; void the run") and logs nothing. The widening cap counts distinct non-baseline `(candidate, detector_sha256)` pairs: editing a variant's body and re-scoring is a new candidate; re-scoring the same pair is not. Rows written before PR #708 have no sha and count as their own pair. The log is append-only by procedure. `redo-sample --freeze --detector X` (non-baseline) records `tune_row_sha256`, `tune_log_sha256`, `tune_log_bytes`, `tune_run`, `tune_manifest_sha256`, `tune_labels_sha256`, `tune_scored_pairs_sha256` and `tune_projects_dir_sha256` in `frozen.json`; `redo-score` refuses a run whose log prefix no longer hashes to that value, whose prefix no longer passes the freeze gate for the same row, or whose labels digest or tune set differ. That detects deletion or rewriting AFTER freeze only. Editing or deleting the log BEFORE freeze cannot be detected by the tool: it is a procedure violation. A frozen.json whose `detector_variant` is the baseline but carries any tune provenance is refused (an edited variant). A frozen.json edited so that every field looks like a baseline freeze (variant and all provenance fields) is indistinguishable from one; that edit is likewise a procedure violation the tool cannot detect. Hashes and byte lengths only. |
| Freeze gate | `redo-sample --freeze --detector X` refuses a non-baseline X unless exactly one live tune run exists and X's rows at the CURRENT detector sha256 are the strict argmax of overall unweighted tune F1 in the canonical tune set. That set is fixed by the run, not by X: the identity of the run's first complete row (same `tune_run`, tune manifest sha256, labels digest, scored-pair digest, projects-dir digest and `n_unclear`), complete rows only (n_lost 0: every manifest pair labelled and its transcript re-read). The set must hold a `v2` row with a defined F1 and a row for EVERY other non-baseline candidate that has any tune row at the current sha; each competitor `(candidate, sha)` of another candidate counts at its maximum F1 in the set, X at its minimum over its current-sha rows (X's own rows at older shas are not competitors, but still count as widenings); a tie fails closed. Each cause (no log, no row, stale sha, tune runs not exactly one live, no complete scoring, no identity, incomplete tune scoring, not in the canonical set, no baseline, incomplete comparison, undefined F1, not argmax, tie) prints its own counts-only refusal. At freeze the digest of the label files named in the canonical row is recomputed from the run dir and `owner_done.json` is re-validated; a difference refuses (exit 2, "labels on disk changed since canonical scoring; restore the original label files or void the run"; re-scoring cannot help, because a re-score with other label files is refused by the labels lock above). There is no judge-only escape: design section 3 makes the owner the final say on the F stratum, so a canonical scoring without the owner pass is not allowed. Nothing is written on refusal. |
| Procedure-only | The tool cannot detect: editing or deleting `tune_log.jsonl` BEFORE a freeze; writing a rigged labels file and scoring it as the run's FIRST complete scoring; editing transcripts in the projects dir; drawing the tune pool from a curated dir with `--allow-nondefault-projects-dir` (recorded, not prevented); voiding a tune run to draw a new one (recorded with its reason in later `frozen.json`, and every current-sha candidate must be re-scored there); and editing `redo_signal.py` so a competitor scored only at an older sha on a voided run drops out of the comparison (needs a source edit and a void). Also by procedure: (a) the label-file set is fixed at the first canonical scoring, and `--labels` subsets are possible (a subset without `labels_owner.jsonl` is never canonical); (b) non-canonical and incomplete scorings still print F1, so a person can peek at results before committing (narrow: only the printed counts, nothing is bound); (c) transcript decay: a candidate first scored after a transcript expires gets `n_lost` > 0, and freeze then refuses as incomplete. That fails closed; score all candidates promptly after labelling. These are procedure violations. |
| Widening dead end | Once both widenings are used, any edit to `redo_signal.py` (even a comment) changes the detector sha256: no non-baseline variant can be tune-scored again (a new pair would be a third widening) and none can be frozen (freeze needs the row at the current sha). Only `v2` stays freezable. |
| Incomplete run dirs | A run directory under `redo_validation/` without a readable `manifest.jsonl` and `frozen.json` makes census/freeze/tune refuse, naming the run id(s) (never a path); recovery is to move it aside or remove it. |

| Item | Value |

## `text_job_fail_closed.jsonl` (LC-12e)

| Item | Value |
|---|---|
| Rows | `c` (refusal code: `CHZ-FC-ROUTER-TEXT-JOB-ELIGIBILITY`, `CHZ-FC-ROUTER-TEXT-JOB-CUT-CHECK` or, LC-12f, `CHZ-FC-ROUTER-TEXT-JOB-LIVE-CHECK`, or, LC-12g, `CHZ-FC-PROVIDERS-TEXT-JOB-OVERFLOW-SWITCH`), `ts`, and `e` (exception class name, when an exception caused the refusal). No prompt text, no model name, no path. |
| Writer | `eligibility_routing.record_fail_closed`, called when a local-only (`LLM_ROUTER_LOCAL_TEXT_JOBS` unset) `llm_text_job` is refused because its eligibility step or cut-site check raised, or (LC-12f) because the pre-dispatch read of the model's live `/api/tags` row did not match its pass. Best-effort: a failed write is recorded with `failopen` code `CHZ-FO-FAIL-CLOSED-UNRECORDED`, and the refusal still happens. |
| Kept | Two generations of 256 KiB via `capped_log` (`eligibility_routing.FC_MAX_BYTES`): `<name>` and `<name>.1` (older). The oldest generation is dropped on rotation; a generation can exceed the cap by one row. |
| Why 256 KiB | A row is about 80 bytes, so about 3,000 rows per generation. Each row is a crash; more than that in 7 days is one recurring bug, and the count only needs to be non-zero. |
| Reads | `eligibility_routing.fail_closed_counts` (the `text_job_fail_closed` counter in `llm-router doctor`) tail-reads each generation to its cap and counts rows with `ts` at or after the cutoff (now minus 7 days, `FC_WINDOW_S`), so one old crash does not alarm forever. A store with lines but no valid row reads as unknown ("present but unparseable"), never 0; a generation that cannot be opened (e.g. a permission error) reads as unknown ("unreadable"). |
| File mode | Files are created 0600, including the new live file after rotation. |
| Concurrency | Append takes no lock: one `O_APPEND` write. Rotation uses a non-blocking lock on the sidecar `text_job_fail_closed.jsonl.lock` (empty, created on the first rotation and kept); a writer that cannot take it skips rotation. |

## File modes of every state file (W0-4, PRD S7)

| Item | Value |
|---|---|
| Rule | Every file under `LLM_ROUTER_HOME` (`paths.state_path`) is 0600 and every directory 0700, whatever the umask. SQLite `-wal`, `-shm` and `-journal` files take the mode of the main database file, which is created at 0600 first (`state_files.connect_sqlite`). |

Symlinks are skipped, never followed, and nothing outside the state directory is changed. A file written at a wider mode after the marker exists is not repaired until the writer is routed through the helper; delete the marker to run the repair again. |
| Not covered | Writers listed in the baseline (they create files at the umask default until routed), and files other tools place under the state directory. |
