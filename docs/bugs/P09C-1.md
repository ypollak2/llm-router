## P09C-1. The full status line spent ~500 ms (live p95 2,435 ms) in sixteen sequential subprocesses

- **Symptom (2026-10-09).** PRD bar: statusline p95 <= 100 ms (NFR-LAT, R-VAL-1, P0.9-c). The gap matrix
  gave a live p95 of ~2,435 ms; `hook_latency.jsonl` statusline rows on this machine: n = 84, p50 549 ms,
  p95 1,856 ms (nearest rank, n-1 scale), max 4,431 ms (sampled with `LLM_ROUTER_STATUSLINE_TIMING=1`,
  window 2026-10-08T21:37Z to 2026-10-09T09:32Z; read-only copy of the ledger). Re-measured outside in with `scripts/statusline_wall.py` on a copy of the live
  state: p50 458 ms, p95 509 ms cold (n = 190, load1 <= 4).
- **Cause.** `statusline-command.sh` ran, per render: three `python3 -c` to read `cwd`,
  `transcript_path` and `model` out of one JSON (~20 ms each); five more for quota age, the fallback flag,
  two percentages, and the reset time (~76 ms together); a parse of the WHOLE transcript for the context
  figure (~63 ms at 11 MB, growing with the session); an interpreter probe loop plus `import llm_router`
  and the `dashboard_data` union for the money figure, and a `sqlite3` process for the route mix (~165 ms);
  a proxy probe (~22 ms), the health check (~54 ms) and the last-route lookup (~40 ms). Phase medians,
  40 runs, load1 3.7: sum 537 ms, each phase carrying ~5-6 ms of the table's own timing perl. Nothing in
  them needs to be fresh to the second, and any one of them blocks on a contended disk or CPU, which is
  how the live tail reaches seconds.
- **Fix.** The segments are computed by one detached process (`statusline_segments.py`, stdlib-only at
  import) into `statusline_seg_<session>.kv`; the script reads that file with `read`. The hot path
  starts no process but `date` (bash 3.2 has no clock builtin). Staleness is visible: `cached <age> ago`
  past 90 s. The quota `°` marker keeps its old quirk (only rendered when the usage-refresh script is
  installed) so output stays byte-identical; changing it is a separate change.
- **Test.** `tests/test_p09c_statusline_budget.py`: the warm path may start only `date` (fails on the
  previous script, which starts python3, sqlite3, cat, sed and others), a stale cache is rendered at once
  and refreshed in the background, a cache the refresher stopped updating is marked, a transcript newer than
  the cache triggers a refresh, the tail read equals the full scan on random transcripts. Wall clock:
  `scripts/statusline_wall.py` (not a unit test: wall-clock assertions are flakes under load, L22).
