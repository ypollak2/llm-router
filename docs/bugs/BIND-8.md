## BIND-8. Every `codex exec` outside the delegated agent-route run started without `--ignore-rules`, and nothing stopped a Codex CLI that does not know the flag

- **Symptom (2026-11-03).** BIND-6 closed the execpolicy hole for the delegated agent-route run only. A user rule such as `prefix_rule(pattern=["curl"], decision="allow")` makes Codex run the matching command outside its sandbox, with network, and `--ignore-user-config` does not stop it from loading the rule; the owner's rules allow `curl`, `git push`, `gh pr merge` and `gh run`. Every other `codex exec` in the repository was started without `--ignore-rules`: the router chain (`router.py`), the MCP tool `llm_codex`, the session broker, the model evaluator and calibration (all five through `run_codex`), the agentic adapter (`CodexAdapter._codex_argv`, a third argv that also lacked `--ignore-user-config`: N2 of the re-review), `scripts/bench_backend_quality.py`, `scripts/cls_send_lib.py`, and the command line `llm_select_agent` recommends to the model. Live, with the flag-less argv `run_codex` builds for the first five: a stub model asked for one `curl`, a rule allowed it, and the canary listener was hit; with the flag it was not (`canary_hits=1 curl_http=200` against `canary_hits=0 curl_http=0`, n=1 run per arm through the real `llm_codex`, codex-cli 0.161.0, macOS seatbelt, 2026-11-03). The sites were found by an AST walk of `src/`, `scripts/` and `hooks/` for every `[<binary>, "exec", ...]` list and every `codex exec ...` command string (the census in the test file); the two other places that start the binary, `codex login status` (`seats.py`) and `exec --help` (the probe and `cls_pins.py`), run no model and no command.
- **Cause.** BIND-6 put the flag in the sandbox branch of `codex_exec_args` and left the flag-less callers "to a decision", because a CLI that does not know the flag rejects it and runs nothing, which for the router chain is a silent skip of Codex (checked on codex-cli 0.161.0 with a made-up flag: `error: unexpected argument ... found`, exit 2, no output; no older CLI was available to check). Nobody had listed the places that start the binary, so the adapter's argv (older than BIND-6) was never compared with `codex_exec_args`.
- **Fix.** `--ignore-rules` in every argv: `codex_exec_args` for every sandbox mode (and `None`), `CodexAdapter._codex_argv` (plus `--ignore-user-config`), `scripts/bench_backend_quality.py` and the `llm_select_agent` command line. The capability check: `codex_agent.codex_supports_ignore_rules(binary)` runs `<binary> exec --help` once per binary (from a worker thread in `run_codex`, never on the event loop; 15 s cap; 37-86 ms on this machine, median 39 ms of 10 runs) and keeps a definite answer for the life of the process; a probe that cannot answer (missing or hung binary, failed or empty help) counts as "no" and is not repeated for 60 s. A CLI that does not list the flag is not started: `run_codex` returns `exit_code=1`, `reason_code="no_ignore_rules"`; `CodexAdapter.run` returns a 127 result and runs no process, not even the diff capture; each refusal is one WARNING (`codex_unprotected_refused: ...`) and one `CHZ-FO-CODEX-NO-IGNORE-RULES` fail-open row (detail: the binary path); `is_codex_available()` turns False after the first refusal (a dict read, no I/O), so the router stops offering Codex, and `llm_codex` says the CLI is too old instead of "not found"; agent-route records `codex_failed` with `reason_code=no_ignore_rules` and leaves the task to Claude; the router chain, which built its chain before the first refusal, refuses each Codex entry in it once (two by default) and falls back to the next provider. The benchmark script has no capability check, by choice: it is not a routing path, and a CLI that does not know the flag rejects it and runs nothing, as above (it shows `exit 2: ...` as its error). **Exception (decided, D-345).** `scripts/cls_send_lib.py` is the sender of the closed CLS-DEV study and is hashed into its `PINS-STATIC` (docs/prereg/PREREG-CLS-DEV.md, frozen 2026-10-22, not committed) and into its scrubber self-test result, so it keeps its original argv, without the flag: a changed file makes a pin-verifying run exit 9 (`tests/test_cls_bl.py` pins that for a changed `cls_send_lib.py`). The script is used only by that study, not by routing, and its scripts are not to be run. The census allowlists it by name with that reason and pins its argv as it is (`::test_argv_of_the_cls_sender`), fails on any other `codex exec` without the flag, and fails if the exemption goes stale. Not covered: the benchmark script does not pass `--ignore-user-config`, and the CLS sender passes neither flag; the router chain, the MCP tool and the other `run_codex` callers pass no sandbox flag, so they run in Codex's own exec default and keep its hosted `web_search` tool (BIND-9 closes that for delegated runs only); the agentic adapter's `workspace-write` run keeps Codex's defaults for `/tmp` and passes none of the `sandbox_workspace_write.*` flags of D-357; the flag is not in a version table: the help text is the oracle, so a future Codex that renames it is refused until the name here is updated.
- **Test.** `tests/test_bind_codex_ignore_rules_everywhere.py` (40 cases, run in CI): the census (`::test_the_census_finds_the_known_call_sites_and_nothing_else`, `::test_every_run_site_and_command_line_carries_the_flag`, `::test_a_help_query_starts_no_run`) fails on any new `codex exec` argv or command line; the exact argv of each site (`::test_argv_of_run_codex_at_every_sandbox_mode` x3, `::test_argv_of_the_agentic_adapter`, `::test_argv_of_the_cls_sender`, `::test_argv_of_the_backend_quality_bench`, `::test_the_session_routing_recommendation_names_the_flag`); each real caller launches a stand-in `codex` with the flag and, against a stand-in whose help lacks it, never launches it, falls back, logs the WARNING and writes the row (`::test_each_run_codex_caller_starts_codex_with_the_flag` and `::test_each_run_codex_caller_falls_back_on_a_cli_without_the_flag`, each for the MCP tool, the session broker, the evaluator, calibration and `run_codex`; `::test_the_router_chain_starts_codex_with_the_flag`, `::test_the_router_chain_skips_a_cli_without_the_flag`, `::test_the_agent_route_hook_delegates_with_the_flag`, `::test_the_agent_route_hook_leaves_the_task_to_claude_on_a_cli_without_the_flag` (the real hook, a subprocess), `::test_the_agentic_adapter_starts_codex_with_the_flag`, `::test_the_agentic_adapter_does_not_start_a_cli_without_the_flag`); and the check itself (`::test_the_probe_reads_the_flag_from_the_help_text` x7, `::test_a_missing_or_hung_binary_cannot_answer_and_counts_as_no`, `::test_the_answer_is_asked_once_and_an_unanswered_probe_is_not_repeated_for_a_minute`, `::test_the_probe_runs_off_the_event_loop_once_per_binary`, `::test_availability_and_the_mcp_message_follow_the_check`, `::test_the_refusal_is_a_warning_and_a_fail_open_row_with_the_binary_named`). The conftest stubs the probe to "supported" for every other test (a fake binary path would otherwise read as "no"); a test marked `real_codex_probe` gets the real one. The live case is `tests/test_bind_codex_sandbox_live.py::test_a_rules_allowed_command_does_not_leave_the_sandbox_at_the_mcp_and_router_call_sites` (`requires_codex`, skipped inside an outer sandbox): the control is the old argv and must show the escape. Twenty narrow mutations each turned named tests red (70 failing cases, plus 3 live): `--ignore-rules` dropped from `codex_exec_args` (11, and the 3 live tests), from the adapter (3), from the `llm_select_agent` command line (2), from the bench (2); `--ignore-user-config` dropped from the adapter (2); the refusal ignored in `run_codex` (10) and in the adapter (1); the probe run on the event loop (1); `is_codex_available` ignoring the check (1); an unanswered probe counted as "yes" (2); a failed help counted as an answer (1); the answer not cached (9); the fail-open row dropped (9); the WARNING dropped (6); the flag matched as a bare substring, so `--ignore-rules-file` counts (1); the MCP message saying "not found" (1); a new `codex exec` argv list, and a new command line, in a new file (2 each); a second site in the exempt file, and the exempt site gaining the flag (2 each). Rule: a security flag added to the modes that were reported leaves the same hole on every path that was not named: list every place that starts the binary (by AST, not by memory), pin each argv, and make a missing capability a refusal, not a silent skip.
