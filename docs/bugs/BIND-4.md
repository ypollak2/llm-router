## BIND-4. A delegation the host discarded left no trace, and the router kept spending Codex time on it

- **Symptom (2026-10-04..2026-11-03).** 317 `delegated` rows were void and nothing recorded that: the audit labelled 308 of them "redone" after the fact, and the lever kept dispatching (n=317, `~/.rsi/research/primary-plan/v16/coord/BIND-R1-codex-handoff-20261103.md` section 0). The audit paired a unit with its Agent call by a 900 s time window and paired a neighbouring call for 98 of 406 units (same file, section 4).
- **Cause.** A `delegated` row says "Codex ran", not "the host honoured the deny". It carried no `tool_use_id`, and no hook compared the delegation with what the host did next. The model also had no way to ask for a real sub-agent when the Codex result was not enough: asking again would have cost a second Codex run.
- **Fix.** Every `agent_route_codex` ledger row and every `agent_calls_ledger.jsonl` row written by `agent-route.py` carries the payload's `tool_use_id`. `llm_router/codex_handoff.py` remembers the Agent calls the router denied with a result (in the per-session depth file, so SessionEnd removes it). PostToolUse[Agent] fires only for a call that ran, so `agent-depth-release.py` marks a remembered id seen there as `delegation_void` (ledger row, stderr notice). Three voids in one session open a breaker: no more Codex dispatch in that session (`codex_session_breaker`). The same prompt asked again goes to Claude (`codex_reissue`), which is what the escape hatch in the delivered text promises. The detector rests on a documented host fact, not an observed one: PostToolUse fires after a tool has executed successfully (`tool_response.status` is `completed` for a foreground sub-agent and `async_launched` for a background one), and a permission denial fires PreToolUse only, neither PostToolUse nor PostToolUseFailure (Claude Code hooks reference, PostToolUse and PostToolUseFailure sections, docs copy read 2026-11-03, top changelog entry 2.1.317). Transcripts do not record PostToolUse hook runs, so nothing local shows it; the live canary of the plan (W5) is what does. A background sub-agent that never reaches PostToolUse is not detected.
- **Test.** `tests/test_bind_codex_handoff_state.py` (12 tests: void counted once, ordinary call ignored and writes nothing, breaker per session, TTL, shared depth file not clobbered, fail-open, the real PostToolUse hook), `tests/test_bind_agent_route_handoff.py::test_void_detector_and_breaker_end_to_end_through_both_hooks`, `::test_a_deny_the_host_honoured_is_not_counted_void`, `::test_the_breaker_is_per_session`, `::test_every_ledger_row_carries_the_tool_use_id`, `::test_blocked_unit_row_carries_the_tool_use_id`, `::test_the_escape_hatch_leads_to_a_claude_subagent_not_to_a_second_codex_run`. Narrow mutations each turned a named test red: no `tool_use_id`, breaker off, re-issue guard off, delivered not remembered, detector removed from the release hook.
