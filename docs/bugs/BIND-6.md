## BIND-6. A delegated Codex run could run a command outside its sandbox, with network, and could write `/tmp` and `$TMPDIR`

- **Symptom (2026-11-03).** The independent review of PR #818 at 2b16ddfa reproduced it live on codex-cli 0.161.0: a stub Responses server on loopback played the model and asked for one command, `curl -s -m 5 http://127.0.0.1:<port>/probe`, a canary listener on the same port range, a temp `CODEX_HOME`, the argv the PR built. With no rules file the `curl` failed (exit 7, no hit on the canary: the sandbox's network is off). With `rules/default.rules` = `prefix_rule(pattern=["curl"], decision="allow")` the `curl` exited 0 and the canary was hit, in `workspace-write` and in `read-only` alike (n=1 run per scenario, review section 3). A `decision="forbidden"` rule was enforced in the same runs, which shows the rules load despite `--ignore-user-config`. The owner's `~/.codex/rules/default.rules` has 36 `allow` rules, among them `["curl"]`, `["git","push"]`, `["gh","pr","merge"]` and `["gh","run"]` (read from a copy by the review). So a delegated model reading a prompt with untrusted text could push, merge and fetch with the owner's credentials. Separately `codex debug prompt-input` listed `/private/tmp` and the `$TMPDIR` directory as writable roots next to the work tree, and the coordinators' worktrees live under `/private/tmp`.
- **Cause.** `codex_exec_args` passed `--ignore-user-config` and `--sandbox ...` but not `--ignore-rules`, and an execpolicy `allow` rule makes Codex run the matching command outside the sandbox ("Commands are run outside the sandbox if they are approved by the user, or match an existing rule that allows it to run unrestricted", the binary's own model-facing text). The first push cited `codex debug prompt-input` ("Network access is restricted") as the evidence that the network was off; it shows what the MODEL is told, not what is enforced, and no test ran a command. `/tmp` and `$TMPDIR` are default writable roots of `workspace-write`.
- **Fix.** `codex_exec_args` adds `--ignore-rules` for both delegated modes, and `-c sandbox_workspace_write.exclude_slash_tmp=true -c sandbox_workspace_write.exclude_tmpdir_env_var=true` for `workspace-write`. With `/tmp` closed the run still needs a temp dir for tests and tools, so `run_codex` creates `<root>/.llm-router-codex-tmp/<run-id>` (0700) before a `workspace-write` run, puts it in the child's `TMPDIR`, and removes it after the run (also after a failure or a timeout). Its parent holds a `.gitignore` of `*` (which also ignores itself), so `git status` stays empty and nothing reaches a commit; a parent that is a symlink, or that resolves outside the root, is refused (the run then has no temp dir, and stays in its sandbox); only dirs named like run ids and over a day old are pruned (a killed run's leftovers). Not covered, open: the router chain and the MCP tools call `codex exec` with no sandbox flag and no `--ignore-rules` (their argv is pinned unchanged); the same live scenario with their flag-less argv shows a rule-allowed `curl` hitting the canary too (observed once, 2026-11-03). Adding `--ignore-rules` there is one line and one pin, and makes every Codex call fail on a CLI that lacks the flag, so it is left to a decision. Observed on 0.161.0: `.git` is read-only inside the writable root, so commit, worktree and PR steps of a delegated builder prompt still end in blocked reports, and the gate discards them (BIND-2). Verified on the macOS seatbelt with codex-cli 0.161.0 only; other Codex versions and the Linux sandboxes are untested.
- **Test.** `tests/test_bind_codex_sandbox_live.py` runs the REAL `codex` with a stub model and a canary on loopback, the argv `codex_exec_args` builds (only the model provider swapped), and for every claim a control run with the flag removed that must show the escape or the test is skipped: `::test_a_rules_allowed_command_does_not_leave_the_workspace_write_sandbox`, `::test_a_rules_allowed_command_does_not_leave_the_read_only_sandbox`, `::test_the_work_tree_is_the_only_writable_root` (`/tmp` and the inherited `$TMPDIR` are closed), `::test_the_runs_own_temp_dir_inside_the_work_tree_is_writable`, `::test_the_git_dir_inside_the_root_is_read_only_on_this_codex` (a record, skipped if Codex changes). It is marked `requires_codex` (CI and the default run deselect it; run `pytest -m requires_codex tests/test_bind_codex_sandbox_live.py` where `codex` is installed and outside an outer `sandbox-exec`, where every test skips), so CI runs the argv pins: `tests/test_bind_agent_route_handoff.py::test_exec_args_of_every_delegated_mode_ignore_user_and_project_rules` (both modes), `::test_exec_args_workspace_write_has_the_network_off_and_precedes_the_model`, `::test_built_command_line_of_a_delegated_run` (the real hook launches a stub with the flags), `::test_a_delegated_write_run_has_a_temp_dir_inside_the_repo_that_never_reaches_a_commit`, and `tests/test_bind_codex_run_tmpdir.py` (10: private dir, git-ignored, removed after a run, a failure and a timeout, pruning, symlinked parent refused, read-only and pure-LLM runs get none). Nine narrow mutations each turned a named test red (25 failing cases): `--ignore-rules` dropped (8, including both live rule tests), each exclude flag dropped (3 each, including the live writable-root test), TMPDIR not set (2), run dir not removed (2), symlinked parent followed (1), pruning ignoring the run-id name (1), `.gitignore` that ignores nothing (2), a read-only run given a temp dir (3). Rule: a sandbox claim in a security document needs a test that runs a command, with a control that shows the escape; a prompt-text readout is not evidence.
