## BIND-10. An explicit `LITELLM_LOG=DEBUG` in the user's environment still put LiteLLM's records in front of the JSON of ten hooks

- **Symptom (2026-11-03).** S4's guard (BIND-1) kept LiteLLM's own log handler off the stdout of the ten non-agent-route hooks that import `llm_router`, but only while `LITELLM_LOG` was unset: an explicit value won. The re-review of PR #818 reported that an explicit `LITELLM_LOG=DEBUG` still voids all ten: LiteLLM's record comes out on stdout in front of the hook's JSON, which Claude Code then reads as plain text and drops (the same mechanism that voided 317 of 317 Codex handoffs, BIND-1). The canary reproduces it: with the old guard put back in all ten hooks, the explicit-`DEBUG` cases fail for 10 of 10 hooks (20 of 20 cases: 10 hooks x LiteLLM imported late and early), and the 22 cases with the variable unset all pass (real LiteLLM through the repo's canary, n=1 run each, 2026-11-03).
- **Cause.** The guard was `os.environ.setdefault("LITELLM_LOG", "ERROR")` and set the loggers' levels only when the result was ERROR, on the reasoning that an explicit value should win. LiteLLM's handler (`LevelRoutingStreamHandler`) sends every record below WARNING to `sys.stdout` at the level it reads from that variable, so an explicit DEBUG is exactly the setting that corrupts the decision channel.
- **Fix.** The guard forces it, in the ten hooks and their `hooks/` copies: when the hook runs as a script it sets `LITELLM_LOG=ERROR` before LiteLLM can be imported, and sets the `LiteLLM`, `LiteLLM Router` and `LiteLLM Proxy` loggers to ERROR for a LiteLLM that is already imported. The user's value is overridden for these hooks on purpose (LiteLLM's records still reach stderr at ERROR). `agent-route.py` keeps an explicit value: its `main()` rebinds stdout to stderr until the process exits, which `tests/test_bind_agent_route_stdout.py::test_a_library_that_logs_to_stdout_at_exit_cannot_follow_the_decision` runs under `LITELLM_LOG=DEBUG`. The variable is written with `os.environ.update(...)`: `tests/test_env_registry.py` reads every `os.environ[...]` subscript as an unregistered read.
- **Test.** `tests/test_bind_hooks_stdout_canary.py::test_hook_stdout_is_only_its_json_even_when_litellm_logs`, now run with the environment unset and with `LITELLM_LOG=DEBUG`, LiteLLM imported late and early, for the ten hooks and for `agent-route.py` (60 cases in the file, 22 new); the control `::test_the_litellm_canary_reaches_stdout_exactly_when_the_level_lets_it` shows the canary does reach stdout at DEBUG, so a pass means something. Three narrow mutations each turned named tests red (6 failing cases): the old guard back in `bash-compress` (2) and in `status-bar` (2), and the logger-level loop removed from `session-end`, leaving only the variable, which fails the early-import cases with the variable unset and with DEBUG (2). Rule: a guard that lets the user's environment win over a protocol invariant is not a guard; test it with the value that breaks it.
