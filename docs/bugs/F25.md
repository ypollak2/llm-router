## F25. `llm(task="research")` failed on every call when the premium research chain was empty

- **Symptom.** 2026-10-16 12:48-16:07Z, ledger rows 2481/2483/2485/2491/2492: five `research` calls ended `error_exception`, model `none`,
  no attempt events, labelled profile `balanced`. The MCP client saw "Error executing tool llm". 5 of 5 router-path research calls since
  ledger coverage failed. Diagnosis: coordinator scratchpad `f25-report.md` (2026-10-17).
- **Cause.** No Perplexity key + Claude subscription mode: `tools/text.py llm_research` forced PREMIUM. #382 had removed the only local entry
  of the premium research chain, and the dynamic table drops `anthropic` in subscription mode, so `premium/research` was `[]`. The router
  took `[]` as the whole chain (`router._build_and_filter_chain`, logged at debug only), injects Ollama only for cheap tiers, and raised
  `ValueError("No providers available ...")` before any attempt. The ledger guard mapped it to `error_exception` and wrote
  `get_active_profile()` instead of the call's profile.
- **Fix.** (1) `llm_research` asks the real chain builder whether `research/premium` keeps a model (`_premium_research_reachable`); only then
  does it pass PREMIUM, else it keeps the default profile. (2) The router raises `NoRoutableModelsError` (a `ValueError`) for an empty chain;
  `llm_research` turns it into a refusal naming the empty chain(s), reason `refused_no_research_provider` (`call_identity.refuse_ledger_call`),
  excluded by every shared non-decision predicate and its stdlib copies (statusline, session-end hook v34). (3) An empty dynamic chain
  is logged at WARNING once per (profile, task). (4) `route_and_call` records its resolved profile on the ledger guard
  (`call_identity.note_ledger_profile`); `_ledger_exit` writes it.
- **Not fixed here / superseded by F26 (D-175).** The other empty dynamic chains never fell back to the static chain; F26 adds a last-resort floor for empty TEXT chains (local, Codex/Gemini CLI, Claude CLI subscription). Effect on F25: a research prompt over 2000 chars resolves to `premium`, whose research chain is empty on a subscription machine without Perplexity (Ollama is not injected for premium). Before F26 that call was REFUSED (`refused_no_research_provider`); with F26 the floor answers it, local first. The refusal now happens only when nothing is reachable (no local model, no CLI, no Claude subscription, no key). Pinned by `tests/test_f26_empty_chain_floor.py::test_long_research_prompt_on_the_incident_machine_is_answered_by_the_floor`; F25's refusal tests run on a nothing-reachable fixture.
- **Test.** `tests/test_f25_research_empty_chain.py` (9 tests; on unmodified main 7 fail, the 2 preservation tests pass). Mutants, each red:
  always escalate; refusal written as `error_exception`; warning removed; ledger guard uses the active profile.
