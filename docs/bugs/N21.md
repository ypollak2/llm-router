## N21. A harness session tripped the live quality breaker, and breaker refusals left no ledger row

- **Symptom.** M0-3 rerun2 (2026-10-10 14:25-14:35Z, evidence `~/.rsi/research/primary-plan/v16/m03_rerun2_20261010/`): two headless sessions tagged
  `LLM_ROUTER_SESSION_KIND=research` called `llm(task="code")` 20 times and discarded every answer (replied DONE). `mcp_llm:code` opened at 14:34:49Z
  with a 24 h cooldown, which turned off live code routing for every session. Calls A10 and B10 got "quality_breaker: mcp_llm:code OPEN ... Do this
  yourself", wrote no ledger row, and M0-3 scored 18/20.
- **Cause 1.** `quality_breaker._fetch_class_units` read `northstar.units()` without looking at `session_kind`. A discarded answer is outcome
  `discarded` (a failure in `_FAILURE_OUTCOMES`); a session that discards on purpose therefore reads as 20 of 20 failures.
- **Cause 2.** `consolidated.llm()` returned the refusal text straight from `_quality_breaker_block`; no writer ran, and no predicate knew a breaker row.
- **Rule chosen (1).** Units whose `session_kind` is `research` or `harness` are dropped at the breaker's input (`quality_breaker.NON_ORGANIC_KINDS`),
  in `_fetch_class_units` and `dry_run`, so state, probes and the dry run all agree. `organic`, `headless` and untagged (`None`) still count.
  Why not "mark research outcomes `unknown`": the outcome is computed per unit in `northstar` from the transcript and shared by NS/D1/D2/kpi, which
  already filter by kind; changing it would move reports for no breaker benefit, and `unknown` units still occupy the window. Why untagged counts:
  dropping `None` would blind the breaker for any session whose SessionStart hook never ran. Why `headless` counts: `claude -p` doing real work is
  real traffic. `synthetic` is not a kind in `session_kind.VALID_KINDS`; synthetic callers use `research` or `harness`.
- **Other consumers of the same units.** Only the breaker needed the change: `northstar.report`, `kpi` NS/D1/D2/D3 and `current_session_line` already
  select by kind or are per-session. Every breaker caller (UserPromptSubmit, Agent, Stop hooks, `zero_claude_edit`, `llm`, `llm_act`) goes through
  `should_route`, so one input filter covers them all.
- **Fix 2.** `cost.log_breaker_refusal` (via `log_route_error`, same writer, dedup and session source as LEDGER-ERR-1) writes one `usage` row and one
  `routing_decisions` row per refused `llm()` call: `reason` / `reason_code` `breaker_open`, caller's session id, `provenance` from `_write_provenance()`
  (runtime in production), success=0, 0 tokens, $0, no model. A fresh correlation id per call; fail-open. `llm_act` refusals are not written (not the
  `llm()` path, not in M0-3).
- **Shared predicates.** `provider_classes.SQL_NOT_ERROR_ROW`, `SQL_REAL_DECISION`, `real_decision_sql`, `real_decision_sql_async`, `is_non_decision_reason`
  now exclude `breaker_open`. The two stdlib-only copies (`statusline_segments.mix_segment`, `hooks/session-end.py _REAL_DECISION`) carry the same term.
  Because every LEDGER-ERR-1 consumer uses these predicates, routing metrics, bandit, judge enqueue, misroute audit, cost readers and the dashboards
  exclude the rows with no per-consumer change. `cost.log_routing_decision` skips the provider allowlist for the reason like it does for `error_*`.
- **Test.** `tests/test_n21_breaker_harness_ledger.py` (10 tests). On unmodified main 7 of 10 fail. Mutations: filter off -> 3 fail; refusal write removed ->
  row test fails; `breaker_open` removed from `SQL_REAL_DECISION` -> 2 fail.
- **M0-3 procedure notes.** A harness or research session must not be able to trip a live breaker. (1) Before a run, tag sessions with
  `LLM_ROUTER_SESSION_KIND=research` AND confirm the tag file `session_kind_<sid>.json` exists in the state dir (a session whose SessionStart hook never ran is
  untagged and counts). (2) After a run, check `llm-router northstar` / `quality_breaker.json` for any class that opened during the window. (3) Never score
  a run whose window shows a refusal as a routing failure: a `breaker_open` row is a refusal, not an error. (4) Run the harness with `LLM_ROUTER_HOME` pointed
  at a scratch dir when the goal is to not touch the live breaker state at all.
- **Residual.** An untagged harness session (no hook, no env) still counts. The organic breaker can still open from a real organic failure streak, as designed.
