## F90. `test_unknown_is_na_never_blank_or_zero` failed about 1 run in 16

- **Symptom.** `tests/test_p35_why.py::test_unknown_is_na_never_blank_or_zero` was flaky, roughly 1 failure in 16 runs.
- **Cause.** The test asserted on the whole rendered output (`": 0"` must not appear). The render contains a uuid4-hex trace id, and when that id starts with `0` the substring `": 0"` matched the id, not a field value.
- **Fix.** #620 parses the named fields out of the render and asserts n/a on those, so random ids can no longer match. Rule: a test that asserts n/a must parse the named fields, never substring-scan output that contains random ids.
- **Test.** `tests/test_p35_why.py::test_unknown_is_na_never_blank_or_zero` is the guard.
