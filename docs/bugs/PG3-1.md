## PG3-1. Prior answers from the legacy result_cache were injected into unrelated model/system/context

- **Symptom.** `llm_query`/`llm_analyze`/... wrote every answer to `~/.llm-router/result_cache.db`
  (keyed on `sha256(prompt.strip().lower())` only; no model, system prompt, conversation context or
  tools in the key). `context_prep.prepare_prompt` then ran a BM25 search over it and prepended the
  neighbours as "[Relevant prior answers]" to the next request, whatever model, system prompt or
  context that request carried. "yes, do it" answered under context A resurfaced under context B.
  A second store also split hit accounting from the semantic cache (D-R8-5: one result store).
- **Cause.** Two result stores. Only `semantic_cache` has the key from P0.5 (normalised text,
  `ctx_hash` over system + conversation context, project scope). `result_cache.check_dedup`
  (the exact-hit reader) had no callers; the live reader was the context-prep BM25 injection.
- **Fix.** `result_cache.py` is removed. `tools/text.py` no longer writes it (`_cache_result`
  deleted) and `context_prep.prepare_prompt` no longer injects prior answers. Identical requests are
  still answered by the semantic cache in `route_and_call`. Existing `result_cache.db` files are not
  deleted, read, or migrated: the rows carry no model/system/context, so there is no safe key to
  migrate them under.
- **Test.** `tests/test_p05c_one_result_store.py`: `test_a_prior_answer_is_never_injected_into_a_different_context`
  and `test_a_legacy_result_cache_db_on_disk_is_neither_read_nor_modified` (red on main),
  `test_nothing_imports_result_cache` (AST scan over src/, hooks/, scripts/),
  `test_semantic_cache_still_serves_an_identical_request`.
