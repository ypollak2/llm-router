## F26. Empty text chains raised even when a model was reachable

- **Symptom.** 10 text chains were empty after filters on the live machine (Claude subscription, xai key only, Ollama and Codex up): premium/reasoning x research always, premium/reasoning x generate/analyze/code and reasoning x query whenever Codex was down. Empty always raised before any attempt (F25 gave the research door a refusal).
- **Cause.** `router._build_and_filter_chain` takes an empty dynamic chain as the whole chain, never consults the static chain, and injects Ollama for cheap tiers and Codex/Gemini CLI for four task types only.
- **Fix (D-175, option b).** `_empty_chain_floor`, only when a text chain is still empty at the end of the builder: local models (any profile, P0.15 gate), Codex/Gemini CLI, then the static chain re-filtered by `_keep_reachable_providers` (the main filter's predicate; Claude only via the CLI subscription), Claude last (D-116); block/policy/hard-block/map filters re-applied. WARNING once per chain; tier recorded (`call_identity.note_ledger_floor_tier`, `router._FLOOR_TIERS`). Hook for F23: `router.record_floor_tier`. Media keeps raising; the proxy builder passes `last_resort_floor=False`.
- **Test.** `tests/test_f26_empty_chain_floor.py`.
