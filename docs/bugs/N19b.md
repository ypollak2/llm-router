## N19b. The N19 classifier exclusion matched one exact name, so classifier variants and unnamed imports still served code calls

- **Symptom (M0-3 rerun3, 2026-10-10).** An `llm(task="code")` call tried `llmr-classifier-38` and `llamacpp:<hash>`; each burnt a 120 s timeout.
- **Cause.** `discover._CLASSIFIER_ONLY_BASES = {"llmr-classifier"}` compared the bare name before `:`. `llmr-classifier-38` (a qwen3.8 27B Modelfile, `parent_model` qwen3.8) and the two `llamacpp:<sha256>` tags (Ollama llamacpp-runner imports of the qwen3.5 and llmr-classifier blobs) all report `capabilities` with `completion`, template `{{ .Prompt }}`, no SYSTEM line: `/api/show` has no role marker to read (only `nimble:9b` does, caps `["decision"]`, which N19 already handles).
- **Fix.** `_is_non_code_model`: name prefix `llmr-classifier` or `llamacpp:`, or the base name configured as the classifier / decision model by env. `local_classifier` and `decision_classifier` name their model explicitly and never read the filter.
- **Tests.** `tests/test_local_model_hygiene.py::test_n19b_*` (stub HTTP). Mutations checked: exact-name rule, dropping `llamacpp:`, dropping the env role each fail a test.
- **Left alone.** There is no registered ROLES table on main (draft #402 only); if it lands, `_is_non_code_model` is the one place to consult it.
