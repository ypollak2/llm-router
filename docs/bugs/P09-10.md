## P09-10. P0.9 statusline row tests read the store between create and write

- **Symptom.** CI py3.11 run 37901401651 attempt 2:
  `test_statusline_row_carries_the_session_id_from_stdin[full]` failed with
  `ValueError: not enough values to unpack (expected 1, got 0)`. Passes locally.
- **Cause.** `_wait_row` waited for `store.exists()`, but `capped_log.append` does
  `os.open(O_CREAT|O_APPEND)` then `os.write`; the file exists empty in between, so a slow
  runner read zero rows. The product is correct (single append, the reader skips partial
  lines); only the test's wait condition was wrong.
- **Fix.** `_wait_row` polls (15 s deadline, writer takes well under 1 s) until the file ends
  in a newline, then parses. `test_statusline_timing_all_writes_a_statusline_row` uses it too.
- **Test.** Same tests. With a 1 s sleep injected between open and write in
  `capped_log.append`, the old tests (3) fail with the exact CI error; the new ones pass;
  the file passes 30 of 30 runs (28 tests each) in an isolated HOME.
