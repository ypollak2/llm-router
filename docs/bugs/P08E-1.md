## P08E-1. Calls served by the semantic cache had no session-attributed ledger row

- **Symptom.** Live M0-3 run, 2026-10-09: two concurrent sessions each made 10 `llm(task="code")`
  MCP calls. 18 wrote `usage` / `routing_decisions` rows with the right `session_id`; the other 2
  were semantic-cache hits (`semantic_cache_lookups`: 20 code lookups, 2 with `hit=1`) and wrote no
  row anywhere that names a session. Per-session accounting (P0.8 completeness, M0-3 attribution,
  per-action offload, savings per session) silently missed them.
- **Cause.** Two gaps. `semantic_cache_lookups` has no `session_id` column. The cache-hit branch of
  `route_and_call` wrote no `usage` row, and the `routing_decisions` row that
  `_finalize_successful_route` attempts for it is rejected by `_validate_routing_insert` (provider
  `cache` is not a real provider) and swallowed as a `Failed to log routing decision` warning.
- **Fix.** The cache-hit branch writes one `usage` row through `cost.log_usage` with
  `reason="cache_hit"` (`REASON_CACHE_HIT`), provider `cache`, model `cache/<cached model>`, 0 tokens,
  $0, and the caller's `call_identity.call_session_id()` (NULL outside an MCP tool call). Spend and
  savings are unchanged (0 tokens prices to $0 and saves $0). `semantic_cache_lookups` gains a nullable
  `session_id` (additive migration; old rows stay NULL), written for hits and misses. No
  `routing_decisions` row is added on purpose: a replay is not a routing decision, and that table feeds
  the judge queue, the bandit and the offload shares. No prompt text enters either ledger.
- **Test.** `tests/test_p08e_cache_hit_row.py`: a hit through `route_and_call` writes a usage row with
  the caller's session and reason `cache_hit`; a miss writes no `cache_hit` row; no routing_decisions
  row for the hit; session NULL outside an MCP call; migration idempotent. Red on main (3 tests fail).

### Follow-up in the same PR: call counts include cache hits
- **Symptom (review).** The new `provider="cache"` rows were counted as PAID calls by the status-bar
  session counter, the session-end paid list, the weekly digest, the statusline mix, the `share` card
  (`paid_calls`/`total_calls`) and `digest`, and landed in "other" in `routing_health`; the prompt-cache
  hit rate's denominator grew by them.
- **Cause.** Every surface classified "not free, not subscription" as paid; ~8 hooks hardcode
  `_FREE_PROVIDERS`.
- **Fix.** A cache row is its own non-call bucket: excluded from paid, free and subscription counts.
  Definition in `llm_router/provider_classes.py`; hooks keep a `_CACHE_PROVIDER` copy (status-bar,
  session-end, session-start, session-end-clawcode; versions bumped, hooks/ and src copies identical).
  Package surfaces: statusline `mix_segment`, `commands/share.py`, `digest.py`, `routing_health.py`
  (excluded from every rate), `cost.get_cache_savings` (`usage.cache_hit` is the
  provider prompt cache and nothing sets it on a semantic-cache row, so only the denominator is fixed).
  Spend and savings stay unchanged (the rows are 0 tokens, $0).
- **Test.** `tests/test_p08e_cache_hit_row.py`: one test per surface on a seeded usage.db (paid + free +
  cache row), a hook-copy test (every copy defines `_CACHE_PROVIDER = "cache"`, hooks/ and src copies
  identical), and the denominator test. All red before this change.
