## F22. The Codex chain offered `codex/gpt-4o-mini`, a model the Codex CLI rejects, even with `LLM_ROUTER_CODEX_MODELS` set

- **Symptom (read 2026-10-17).** Live ledger `execution_events`: most routed Codex calls first tried
  `codex/gpt-4o-mini`, which the Codex CLI rejects ("Model metadata for `gpt-4o-mini` not found",
  HTTP 400). Each burned one failed attempt (~4-5 s) before the next model answered. Daily counts of
  that failed first attempt: 2026-10-10 14, 2026-10-15 8, 2026-10-16 15. The live config sets
  `LLM_ROUTER_CODEX_MODELS=gpt-6-astra` (D-118), so no Codex model other than gpt-6-astra should
  have been tried.
- **Cause.** `src/llm_router/policies/standard.yaml` named `codex/gpt-4o-mini` in the BUDGET
  query/generate/analyze/code chains and `codex/gpt-4o` in the BALANCED ones (and in `workhorses`).
  `codex_agent._load_codex_models` already documented both as rejected and honoured
  `LLM_ROUTER_CODEX_MODELS`, but only the router's Codex injection (`router.py`, `CODEX_MODELS[:2]`)
  used it. Injection adds entries and never removes the policy's literal, which sat earlier in the
  chain (BUDGET/query: index 2, after the two Ollama entries), so it was tried first. Both the static
  path (`profiles.get_model_chain`) and the session-start dynamic table (`dynamic_routing`) read the
  same literal from `ROUTING_TABLE`. A29 named this gap and left it open.
- **Fix.** The shared chain-load path (`policy._resolve_chain`, used for `chains`, `workhorses` and
  `fallback_chain_complex` of every policy file, bundled or user) maps a `codex/<m>` entry whose
  `<m>` is not in `CODEX_MODELS` to `codex/<CODEX_MODELS[0]>`
  (`codex_agent.accepted_codex_entry`): the `LLM_ROUTER_CODEX_MODELS` choice when set, else the repo
  default (`gpt-5.5`). The slot keeps its position; a second Codex entry that lands on the same model
  is dropped; non-Codex entries are untouched. `standard.yaml` now names `codex/gpt-5.5` in those
  slots. `profiles.is_free_external_model` treats any `codex/*` as free, so the pressure reorder
  still ranks the BALANCED Codex slot first (it matched the literal `codex/gpt-4o` before). An
  explicit `model_override` or pin is not rewritten.
- **Test.** `tests/test_f22_codex_chain_model.py`: no bundled policy file names a Codex model outside
  the default set; the loaded standard policy, `ROUTING_TABLE` and the dynamic table hold exactly
  `codex/gpt-6-astra` in each affected BUDGET/BALANCED tier when `LLM_ROUTER_CODEX_MODELS=gpt-6-astra`
  (fresh interpreter) and `codex/gpt-5.5` when unset; `router._build_and_filter_chain` with Codex
  available offers no `codex/gpt-4o(-mini)`. Mutation check: restoring one `codex/gpt-4o-mini`
  line fails 1 of 26 tests; disabling the rewrite fails 12; both (origin/main state) fail 21.
