## N20. keep_alive fell back to -1 (pin forever) when its setting was missing

- **Symptom (found 2026-10-10).** A forever-pinned qwen3.8 contributed to an Ollama hang/eviction.
- **Cause.** `warm.edit_keep_alive()` returned -1 for an unset/empty `LLM_ROUTER_LOCAL_KEEP_ALIVE`, and
  `proxy/backends.DEFAULT_KEEP_ALIVE` (also the `--keep-alive` default) was -1.
- **Fix.** Both default to 600 s (`warm.DEFAULT_KEEP_ALIVE_S`). An explicit `-1` (env var or `--keep-alive -1`) is still
  passed through. Grep of `src/` found no other `keep_alive` -1 default (`local_classifier` defaults to `30m` and
  honours `LLM_ROUTER_CLASSIFIER_KEEP_ALIVE`). `docs/proxy.md` updated.
- **Test.** `tests/test_local_model_hygiene.py::test_n20_*`; `tests/test_warm_plan_3_7.py` and
  `tests/test_ollama_watchdog.py` expectations moved from -1 to 600. All fail on main.

### N20b. num_ctx 131072 overrode the server context

- **Symptom (2026-10-10).** Server runs `OLLAMA_CONTEXT_LENGTH=32768` (verified 14:06Z) but `/api/ps` showed
  `qwen3.8:latest` at context_length 131072, costing memory.
- **Cause.** `local_models.NUM_CTX` pinned `qwen3.5:latest` and `qwen3.8:latest` to 131072 and every caller sends it.
- **Fix.** Both entries removed; they take `DEFAULT_NUM_CTX` 32768. Still configurable: `LLM_ROUTER_LOCAL_NUM_CTX`,
  `LLM_ROUTER_PROXY_NUM_CTX`, `LLM_ROUTER_OLLAMA_NUM_CTX`, `--num-ctx`, or a table entry. Tests that pinned 131072
  (`test_m3_4_*`, `test_i2*`, `test_proxy_local_mode`) now expect 32768.
