## P2.7-1. An `opus:` pin was lost when the prompt was longer than 8000 characters

- **Symptom.** A prompt such as `opus: ` followed by 20000 characters was not pinned to Opus; the
  tier policy classified it as an unprefixed prompt. Reproduced by `test_long_pin` on main caaf8d28
  (before the fix, `explicit_opus_pin` returned False for that body).
- **Cause.** `proxy/escalation.explicit_opus_pin` read `tier_text(body, limit=8000)`, which keeps the
  LAST 8000 characters of the newest human turn, so the leading `opus:` was cut off. Its own
  docstring said it checked the untruncated turn.
- **Fix.** Prefix detection (`escalation.explicit_override` / `explicit_pin`) parses
  `steps.newest_human_text(body)` untruncated through `llm_router.prefixes.parse`.
- **Test.** `tests/test_p27_proxy_prefixes.py::test_long_pin`: a 20000-character `opus:` prompt on a
  Sonnet request is served on Opus, through `decide()` and through the ASGI door.
