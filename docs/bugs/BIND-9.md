## BIND-9. A delegated Codex run was still offered Codex's hosted `web_search` tool, which the sandbox's network setting does not cover

- **Symptom (2026-11-03).** Owner decision D-357 gives a delegated run no network (`sandbox_workspace_write.network_access=false`, BIND-2). The re-review of PR #818 pointed out that Codex also offers the model a hosted `web_search` tool. Checked on codex-cli 0.161.0 against a stub Responses server on loopback, which records the `tools` of each request (no model call, temp `HOME` and `CODEX_HOME`, n=1 request per setting): with the argv the PR built, in `workspace-write`, in `read-only` and with no sandbox flag, the model is offered `exec_command, write_stdin, request_user_input, view_image, multi_agent_v1, get_goal, create_goal, update_goal, web_search`. The model provider runs that tool, outside the local sandbox, so a delegated run reading untrusted text could put what it knows in a search query and read what comes back. This check shows the tool is offered; it does not show a search being run, because a stub is not a provider.
- **Cause.** `codex_exec_args` closed the sandbox's network and said nothing about the tool list, and `web_search` is on by default. SECURITY.md's "the network is off" was true of the commands the model runs, not of the tools the provider runs for it.
- **Fix.** `-c web_search="disabled"` (`codex_agent.WEB_SEARCH_OFF`) after the sandbox flags of both delegated modes (`workspace-write` and `read-only`), and in `CodexAdapter._codex_argv` whenever it sets a sandbox. The key was read off the binary, not guessed (`codex debug prompt-input` renders the messages the model sees, not its tools, so the stub's request body is the readout): against the same stub, `web_search="disabled"` removes the tool in `workspace-write` and in `read-only`, `"cached"` and `"live"` keep it, the older `tools.web_search=false` and `--disable web_search` change nothing, and a bad value is a config error that names the valid ones (`unknown variant 'bogus', expected one of 'disabled', 'cached', 'indexed', 'live'`). The pure-LLM callers (no sandbox flag: the router chain, the MCP tool, the broker, the evaluator, calibration) keep Codex's default; they are not delegated agent runs.
- **Test.** The exact argv of each mode and of the adapter, with and without a sandbox: `tests/test_bind_codex_ignore_rules_everywhere.py::test_argv_of_run_codex_at_every_sandbox_mode` (3 cases: only a delegated run carries it), `::test_argv_of_the_agentic_adapter`, and the real hook launching a stub (`::test_the_agent_route_hook_delegates_with_the_flag`, `::test_the_agentic_adapter_starts_codex_with_the_flag`). Live, on the real binary: `tests/test_bind_codex_sandbox_live.py::test_the_hosted_web_search_tool_is_not_offered_to_a_delegated_run` reads the tools the stub model is sent, in `workspace-write` and `read-only`; its control drops the flag and must still see `web_search` offered, or the test is skipped (`requires_codex`). Three narrow mutations each turned named tests red (8 failing cases, plus 1 live): the flag dropped from `codex_exec_args` (3, and the live test), the key replaced by the old `tools.web_search=false` (3), the flag dropped from the adapter (2). Rule: "no network" for a delegated agent is a statement about every tool it is offered, not only about its commands; read the tool list the model receives.
