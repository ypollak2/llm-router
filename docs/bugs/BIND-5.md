## BIND-5. Blocks used only the deprecated decision shape and told the model not to redo the work

- **Symptom.** All six block emissions in `agent-route.py` printed only the top-level `{"decision": "block", "reason": ...}` pair, which current Claude Code documents as deprecated and honours through a compat shim, while `enforce-route.py` prints both shapes for that reason. The delivered Codex text read "Use this result directly as the subagent's output — do not re-do the work", the framing a model refused as a prompt injection in three of three controlled runs on 2026-09-13 (a disposable fixture, Sonnet, a hook denying Read and Bash with a marker while the real file held a sentinel: the marker text was named as an injection in every run, n=3 runs). The router's Bash substitution uses the opposite framing, and of 1,332 such denies the model moved on without re-running the command in 1,280 (n=1,332, `~/.rsi/research/primary-plan/v16/coord/BIND-R1-codex-handoff-20261103.md` section 2.6). Neither was observable before: no clean deny had ever been delivered, because of BIND-1.
- **Cause.** The block paths were written before the deprecation and never moved to `hookSpecificOutput.permissionDecision`; the result text was written as an instruction.
- **Fix.** `_deny()` emits `decision`/`reason` plus `hookSpecificOutput {hookEventName: PreToolUse, permissionDecision: deny, permissionDecisionReason}` for every block. `_result_message()` delivers a routed result the way `tool_intercept.py` delivers a substitution: nothing failed, the source is named, the text sits in an untrusted-data fence with tag-shaped sequences defanged (`hook_payload.untrusted_block`), and the escape hatch is in the message (call the Agent tool again with the same prompt; the router will not hand it to Codex a second time). The `[NS1] agent_route_codex` attribution marker is kept.
- **Test.** `tests/test_bind_agent_route_handoff.py::test_delegated_block_is_a_deny_in_both_shapes`, `::test_other_blocks_are_a_deny_in_both_shapes` (nesting, concurrency, blocked_reasoning), `::test_budget_block_is_a_deny_in_both_shapes`, `::test_cli_delegation_block_is_a_deny_in_both_shapes`, `::test_a_model_pin_stays_an_allow`, `::test_result_is_framed_as_the_subagents_result_not_as_an_order`, `::test_forged_tags_in_the_codex_answer_are_defanged`. Mutations: `_deny` without `hookSpecificOutput` turns 6 tests red; adding "do not re-do the work" to the text turns the framing test red. Whether Claude Code applies the deny and the model accepts a long Codex report as delivered here is NOT shown by these tests; it is the live canary in the plan (a stub answer, one real Claude run) and the success bar measured on organic sessions.
