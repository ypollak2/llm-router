## BIND-2. Codex ran read-only, so most delegated answers reported blocked work, and the router handed those over as the sub-agent's result

- **Symptom (2026-10-04..2026-11-03).** 314 of 317 delegated outputs mention read-only or sandbox, and 269 (85%) also say blocked, cannot or unable to (keyword screen over the delegated texts, n=317, `~/.rsi/research/primary-plan/v16/coord/BIND-R1-codex-handoff-20261103.md` section 2.8). A hand read of 9 found 8 that end "not performed", "needs a write-enabled session" or "read-only permissions prevented the worktree or tests". The prompts came from coordinator sessions that ask a sub-agent to clone, run tests, open a PR and write a report.
- **Cause.** `run_codex` passed no `--sandbox` flag (`src/llm_router/codex_agent.py`), and `codex exec` then runs read-only. `_is_codex_suitable` filters on task-type words and a multi-file-write phrase only. Nothing checked whether an answer reported work NOT done, so a "blocked" report was denied-through to Claude as if a sub-agent had finished.
- **Fix.** `run_codex(sandbox=...)` and `codex_exec_args()` take a mode, `workspace-write` (with `-c sandbox_workspace_write.network_access=false`) or `read-only`; `danger-full-access` cannot be requested through the function. The hook's `_codex_sandbox_plan()` picks the mode from the session's directory (the hook payload's `cwd`, not the hook process's), applying D-357 as the coordinator ruled it on 2026-11-03, "write in repo": (1) a session inside a git work tree (`git -C <cwd> rev-parse --show-toplevel` succeeds) runs `workspace-write`, and the work tree's top level is both the writable root and Codex's `-C` directory (a session in a subdirectory still writes at the top level), unless that top level is `$HOME`, the account's own home directory, a directory above either, or `/`; (2) every other session, meaning one rooted at the home directory, outside any repository, or inside a repository at or above the home directory, runs `read-only` in its own directory, and its blocked answers are discarded like any other (below), so Claude's sub-agent does the task; (3) a session rooted at `/` is refused (`codex_unsafe_cwd`, no run). Two traps in `git rev-parse` are closed, and both reproduce with git 2.50.1 on this machine. With `GIT_DIR` set, a plain directory answers itself as the top level, so `GIT_DIR`, `GIT_WORK_TREE` and `GIT_COMMON_DIR` are removed from the environment of the call. A repository's own `core.worktree` makes `--show-toplevel` print an unrelated directory, so a top level that does not contain the session directory counts as no repository. The network is off in both modes and every command a delegated run executes stays inside the sandbox: that needs `--ignore-user-config`, `--ignore-rules` and, in workspace-write, the `/tmp` and `$TMPDIR` exclusions of BIND-6, which also records how it was found and how it is tested on the real binary (`codex debug prompt-input` shows what the model is told, not what is enforced). The Phase-2 CLI delegation uses the same plan and has the same blocked-answer gate as NS3 (`_discard_blocked_codex`), and the `delegated` and `codex_blocked` ledger rows carry the `sandbox` the run had. Pure-LLM callers pass no sandbox and their argv is unchanged. A reply that says the environment stopped the work (`_blocked_marker`: an environment phrase and an inability phrase in one sentence, or a conclusive phrase such as "Resume in a write-enabled session") is not delivered: the unit is logged `codex_blocked`, no saving is booked, and the Agent call is allowed. `northstar` counts `codex_blocked` as a discarded attempt so those runs stay in the denominator. Detector calibration on the delegated texts above (n=317, produced read-only, texts joined from `~/.rsi/research/primary-plan/v16/coord/BIND-R1-codex-handoff-20261103.md` section 2.1 data): 300 flagged; of the 211 whose end was captured, 207 flagged, and the 4 not flagged were finished reviews with a verdict. It has not been measured on writable-sandbox answers: after deploy, hand-check 20 bound units (success bar: under 10% blocked).
