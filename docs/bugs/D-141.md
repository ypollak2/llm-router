## D-141. MCP tool calls failed with the bare "Error executing tool llm", or hung past the client's wait

- **Symptom.** Claude Code calls to `llm`, `llm_route` and `llm_edit` returned only
  `Error executing tool llm`. Separately, a `task="query"` call routed to four local models hung for
  more than 150 s while other processes held the same Ollama model. The MCP client stops waiting at
  about 120 s, so the user saw a background task that failed later with the same bare text.
- **Cause.** (a) mcp >= 2.2 (live: 2.2.0) turns any unexpected tool exception into
  `UnexpectedToolError("Error executing tool <name>")` and keeps the exception's own message on the
  server. The router's message (`No providers available for research/premium ... Fix: ...`) never
  reached the user. mcp 2.0.0 (uv.lock) still appended the message. (b) No routed MCP call had an
  overall deadline, and each attempt waited out the full 120 s `request_timeout`.
- **Fix.** `IdentityMCPServer.call_tool` runs every tool through `mcp_door.run_door`. A crash comes
  back as `llm-router error: <Type>: <message>` (secret-scrubbed, plus `tried: <models>`).
  Every `route_and_call` door runs under `LLM_ROUTER_MCP_DEADLINE_S` (default 90 s). Local
  `ollama/` attempts are capped at half of it. The cap raises `AttemptCapExceeded`, which sets no
  LOCAL-TIMEOUT-1 cooldown and records no health failure. A cancelled Gemini CLI or Claude Code call
  kills its process group.
- **Test.** `tests/test_d141_mcp_readable_errors.py`: the real server's doors return the readable
  text over the MCP protocol. `test_premise_a_plain_mcp_server_sends_only_the_bare_text` pins the
  cause. Deadline, fall-through and cooldown tests use a real `route_and_call` with a fake
  `litellm.acompletion`. `tests/test_d154_cli_cancel_kills_child.py` uses fake CLI binaries.
