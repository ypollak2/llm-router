## N22. Floor-served calls left only the safety-net usage row, and paid 120 s per extra local model

- **Symptom.** M0-3 rerun3 (2026-10-10, T0 19:57:53Z, `~/.rsi/research/primary-plan/v16/m03_rerun3_20261010/`): calls A2, B2, B6 returned a real
  ollama/qwen3-coder answer and a correct `routing_decisions` row, but their only `usage` row was `provider=none, reason=error_unledgered_exit,
  success=0` (usage ids 1737, 1738, 1746, ~268 s each). The real row (tokens, cost) was missing.
- **Evidence.** `usage.db`: ids are contiguous (1736, 1737, 1738, 1739), so no real row was ever inserted, then deleted. The `routing_decisions` rows
  (2328, 2329) carry correlation ids (779c5a6c, 8dbcd5c5) that no `usage` row has. `routing_quality.jsonl` for the same three calls:
  `route_outcome=degraded`, `fallback_reason=verification_failure`, `chain_errors` = qwen3-coder `gate_failed: syntax: SyntaxError`, then two
  `ollama/llamacpp:<hash>` / `llmr-classifier-38` entries each `litellm.Timeout ... time taken=120.00 seconds`.
- **Cause 1 (missing row).** Not a late write, a dedup or a swallowed exception. All gate-rejected, so the chain was exhausted and
  `route_and_call` served the best rejected answer as the exhaustion floor. That branch called `_finalize_successful_route` (routing row) but never
  `cost.log_usage`; the only `log_usage` for a chain answer sits in the accepted-attempt branch. The guard then correctly saw no `usage` write and
  added its safety-net row.
- **Cause 2 (268 s).** Codex was not involved: `provider_reset.json` benched `codex` until 2026-10-15 17:21Z (set 18:46Z, parsed from the "try again at
  Oct 15th, 2026 6:21 PM" text), `HealthTracker.is_healthy` honours it, and no codex model is in the logged chains. The time was two
  local models timing out at litellm's 120 s after the first answer was already rejected. LOCAL-TIMEOUT-1 (#400) only reorders a timed-out model to the
  back of the chain, so it was still tried; the cooldown is also per process, and each session is its own process.
- **Fix.** (a) The floor branch writes the served answer's usage row (`reason=router_chain`, the caller's session) before finalizing. Rejected
  attempts never wrote usage, so nothing is counted twice. (b) With a rejected answer in hand, an `ollama/` model is skipped when a local model
  already timed out in this call or it is inside its timeout cooldown (`skipped:local_timeout_with_answer_in_hand` in `chain_errors`). A pinned model,
  a remote model, and a call with no answer in hand are unchanged.
- **Quota-exhausted providers.** Already implemented by `provider_reset` (reset time parsed from the error text, persisted, checked by
  `is_healthy`); no change. Not the cause here.
- **Tests.** `tests/test_n22_floor_usage_and_local_skip.py` (4 of 5 fail on main; mutation: dropping the floor `log_usage` fails the usage test,
  disabling the skip fails the three skip tests).
