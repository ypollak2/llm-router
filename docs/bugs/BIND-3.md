## BIND-3. The gpt-5.5 fallback after a usage limit never worked, and a run could be started that the hook limit would cut short

- **Symptom (2026-10-04..2026-11-03).** gpt-5.5 as fallback made 47 attempts and none succeeded: 36 were CLI warnings with no answer (while gpt-6-astra was benched for a usage limit) and 11 were more usage limits (n=47, `~/.rsi/research/primary-plan/v16/coord/BIND-R1-codex-handoff-20261103.md` section 3). 12 runs ended at the 300 s allowance (hook wall 301-302 s of 320).
- **Cause.** `_run_codex_agent_inner` went on to gpt-5.5 after a usage limit on the primary and also when the primary alone was benched (`codex:<model>`), a key the dispatch gates did not read (`_codex_bench_until` looked at the account only). Each fallback spent a window slot and up to a minute of hook time. The allowance counted from the first delegation, not from the start of the process, so time spent before delegating was handed to Codex a second time.
- **Fix.** A usage limit on the primary benches that model and ends the dispatch (`benched`); a benched model or account is skipped before a slot, a budget unit or a process is spent (`_codex_bench_until` now includes `codex:<model>`); the fallback remains only for "this account does not have the primary model". `_delegation_time_left` is capped by `_hook_budget_left()` (the registered hook timeout minus the delegation margin, from the start of the process), and a run is not started with under `_MIN_DISPATCH_SEC` (60 s) left (`codex_failed`, reason code `no_time`). Not changed: a task that needs more than the 300 s allowance still ends at it; a pre-gate cannot know that in advance, so the 12 historical timeouts are not claimed as fixed.
- **Test.** `tests/test_bind_agent_route_handoff.py::test_usage_limit_does_not_start_the_gpt55_fallback` (a stub codex counts its launches), `::test_a_benched_model_is_skipped_before_any_process_starts`, `::test_pre_gate_declines_a_run_the_hook_limit_would_cut_short`, `::test_the_allowance_never_exceeds_what_the_hook_has_left`; `tests/test_codex_delegation_gaps.py::test_quota_on_primary_only_benches_that_model_and_does_not_fall_back`, `::test_the_fallback_is_still_used_when_the_account_lacks_the_primary_model`, `::test_the_fallback_is_skipped_when_the_account_is_benched_in_between`; `tests/test_codex_window.py::test_a_usage_limit_hit_mid_run_still_counts` (one slot, not two). The restore-the-fallback mutation needs both overlapping layers removed (the explicit return and the bench check) to turn the tests red; either alone leaves the behaviour unchanged.
