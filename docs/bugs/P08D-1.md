## P08D-1. `llm_stream` never wrote a usage row

- **Symptom.** Found while enumerating the `usage` writers for P0.8-d: the streaming tool's
  ledger call raised after the stream finished, so no usage row existed for any streamed answer.
- **Cause.** `tools/routing.py` `llm_stream` called `log_usage(provider=..., model=...,
  input_tokens=..., output_tokens=..., cost_usd=..., task_type=...)`. `cost.log_usage` takes an
  `LLMResponse`, a `TaskType` and a `RoutingProfile`; none of those keywords exist, so the call
  raised `TypeError`, outside any `try`.
- **Fix.** Build an `LLMResponse` from the stream's `[META]` frame and pass `task_type`,
  `profile` and `reason="stream_tool"`. A ledger failure now warns instead of losing the answer.
- **Test.** `tests/test_p08d_ledger_completeness.py::test_every_call_into_the_cost_writers_passes_the_field`
  fails on the old call (no `reason=`); the call shape is the `LLMResponse` form every other
  `log_usage` caller uses.
