## P09-SE-1. The Stop hook spent 0.2 s waiting for nobody and 0.3 s (p95 1.8 s) scanning transcripts inline

- **Symptom (2026-10-09).** PRD bar: session-end p95 <= 300 ms (NFR-LAT, PLAN v16 PG4 / P2-G-3).
  Live `session-end` Stop rows, read-only copy of `hook_latency.jsonl`, window 2026-10-08T21:34Z to
  2026-10-09T13:44Z, n = 79 (all carry `phases_ms`): `elapsed_ms` p50 729, p95 3,136 ms (nearest rank,
  n-1 scale), max 11,229; load1 median 2.6, max 18.9. P0.9's detached child had already taken the usage
  fetch, profile rebuild, rescan and model check out of the hook (`test_p09_session_end_bg.py`); the
  tail stayed. Live phases (ms, p50 / p95): `northstar` 343 / 1,819, `spend` 205 / 211, `import` 71 / 292,
  `cumulative` 26 / 164, `render` 42 / 158, `emit` 19 / 82; the other twelve phases sum to < 40 p50.
- **Cause.** Two inline steps:
  1. `_read_session_spend` called `_flush_session_spend_from_mcp`, which wrote
     `session_spend_flush_request.txt` and `time.sleep(0.2)` "for the MCP server to react". Nothing in
     `src/`, `hooks/` or `scripts/` reads that file (the server rewrites `session_spend.json` on every
     routed call), so every Stop paid 200 ms (p50 205) for no effect.
  2. `northstar.current_session_line` -> `report(days=2)` -> `build_sessions` loads every Claude
     transcript modified in the last two days (to fold sub-agent sessions into their parent), so its cost
     grows with recent activity and with disk contention (p95 1,819, max 7,920 ms live).
- **Fix.** (1) The flush request and the sleep are gone. (2) The north-star item is a child step
  (`_refresh_northstar_line`, second in `_STOP_BACKGROUND_STEPS`) that writes `northstar_line.json`
  (`{session_id, line, ts}`, atomic); the Stop reads it. **User-visible change, stated:** the item is the
  share as of the last child run (one turn old, or more when Stops come faster than the child's 15 s claim), and a
  session's first Stop prints no north-star item (it printed `north star: no data` or `too few to tell`;
  the share needs >= 50 units, `MIN_UNITS`, so that first line carried no figure either). A cache for a
  different session id is a miss. Every other output of the hook is unchanged. Repair round 1 (review): the cache is dropped after 600 s (`_NORTHSTAR_MAX_AGE_S`;
  a frozen claim or a resumed session must not show an old line that looks current), the Stop's own
  stdin `session_id` keys the cache and is passed to the child as `--session-id=` (`session_id.txt` is
  shared by concurrent sessions; it stays the fallback), a failed write unlinks its tmp file, and the
  north-star refresh runs before the 8 s HTTPS usage fetch. Hook version 24 -> 26.
- **Not fixed (measured, kept out).** Making `llm_router.cost` / `urllib` imports lazy: `cost` is imported
  again by `dashboard_data.query_window` in `_query_cumulative_savings` on the Stop path, so it only moves
  the cost; the `urllib` change was within noise (import phase 65 vs 75 ms p50), so it was reverted.
- **Test.** `tests/test_p09_session_end_bg.py` asserts the property directly, not by wall-clock:
  the Stop never calls `current_session_line` (recorder spy in `_trap_slow_steps`), never calls
  `time.sleep`, never writes the flush file, and `_flush_session_spend_from_mcp` no longer exists; the child step caches, the next Stop (full and condensed
  modes) shows that line without recomputing it; a cache for another session, a corrupt cache and an
  empty session id are misses; the background steps are pinned in order. Run against the previous hook,
  six of the new/changed tests fail. Outside-in: `se/wall2.py` (scratch HOME with a copy of `usage.db`
  and 60 synthetic transcripts, A/B interleaved, 200 runs per arm, load1 on every row); numbers in the PR.
