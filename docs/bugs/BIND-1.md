## BIND-1. A log line in front of the hook's JSON made Claude Code ignore the decision, so every Codex handoff was void

- **Symptom (2026-10-04..2026-11-03).** The release outcome audit read 0 of 564 routed units used. Of those, 406 were `agent_route_codex` units, and 317 of 317 `delegated` rows were void (`~/.llm-router/north_star_units.jsonl` joined to the hook runs in the session transcripts, n=317 rows, 6 of 22 organic sessions; `~/.rsi/research/primary-plan/v16/coord/BIND-R1-codex-handoff-20261103.md` section 2.1). Each joined run was exit 0, `hook_success`, with stdout = one `[debug    ] Tracked: gpt-6-astra for <task>/<complexity> (agent-route-cli)` line and then the block JSON. The Agent tool_result was "Async agent launched successfully" in 317 of 317, so Claude's own sub-agent ran as well (3.75 M output tokens, 21,961 s of Codex time discarded, same file, section 0). The model pin (an `allow`) was voided the same way when Codex was benched mid-run: a `provider_unavailable_until` warning led the JSON, and the pin was honoured in 1 of 20 runs with a leading log line against 50 of 50 with clean stdout (same file, section 2.2).
- **Cause.** Claude Code treats hook stdout that is not exactly one JSON object as plain text and applies no decision. structlog's default sink is stdout. `hooks/agent-route.py` never configured logging (`auto-route.py` did, with the comment that a log call "would corrupt the payload and silently void routing"), so `_log_cli_savings` -> `model_tracking` printed its debug line first. No test saw it: `tests/test_agent_route_hook.py` replaced `_try_codex_subagent_delegation` with a lambda and `tests/test_codex_delegation_gaps.py` replaced `_log_cli_savings` with a no-op, so no test ran the real path and parsed stdout. The same missing guard was in 10 other hooks this change covers: with a canary that makes library code log one line inside `main()` and at exit, 11 of the 12 scripts the canary test audits put it on stdout (only `auto-route.py` did not; n=12 hook scripts, run against `origin/main` 5c056309 on 2026-11-03, `tests/test_bind_hooks_stdout_canary.py`). `enforce-route.py` leaked the same way when it was first measured; its guard and its stdout tests are in PR #817 (BIND W2, `tests/test_w2_enforce_route_holds.py`), so this change does not touch it. Found while testing the fix: LiteLLM keeps its own handler, which writes every record below WARNING to `sys.stdout` looked up when the record is emitted (default level DEBUG), and a delegated run imports it once the answer is long enough to be judged (`cost.log_routing_decision` -> `judge` -> `providers`); its logging worker logs from an atexit handler, so a line followed the JSON ("Extra data").
- **Fix.** `agent-route.py`: `_init_hook_logging()` points library logging at stderr before anything is routed; `main()` rebinds `sys.stdout` to stderr for the whole run and, as a script, leaves it there until the process exits; `_emit()` writes the one decision through the saved real stdout and refuses a second object; `LITELLM_LOG` defaults to ERROR for the script run. The other 10 hooks that leaked (`agent-depth-release`, `bash-compress`, `cc-usage-track`, `context-capture`, `playwright-compress`, `session-end`, `session-start`, `status-bar`, `subagent-start`, `usage-refresh`) get the same `_init_hook_logging()` as the first statement of `main()`; their `llm_router-hook-version` stamps are bumped so the installer replaces the installed copies. `plugin-install.py` and `codex-stop.py` import nothing from `llm_router` (the second by design, pinned by `tests/test_codex_stop.py`), so no library can log from them, and they are unchanged. The two hiding patches are removed.
- **Test.** `tests/test_bind_agent_route_stdout.py::test_delegated_handoff_is_one_json_object` runs the real hook as a subprocess with a stub `codex` executable (`CODEX_PATH`) and the real `_log_cli_savings`, and asserts `json.loads(stdout)` parses one object while the `Tracked:` line is on stderr; the same file has one test per emit path (`test_codex_benched_mid_run_still_prints_only_the_pin`, `test_cli_delegation_block_is_one_json_object`, `test_direct_subagent_block_is_one_json_object`, the model-pin, breaker, budget and no-decision paths) and `test_a_library_that_logs_to_stdout_at_exit_cannot_follow_the_decision` (LiteLLM forced to DEBUG). `tests/test_bind_hooks_stdout_canary.py::test_hook_stdout_is_only_its_json_even_when_libraries_log` runs the 12 scripts that import `llm_router` and are audited here under the canary (`enforce-route.py` is named in `OWNED_ELSEWHERE` with a pointer to PR #817's tests, and the test fails if a shipped hook is in neither list). `tests/test_agent_route_hook.py::TestAgentRouteEndToEnd::test_main_uses_codex_result_as_subagent_output` is now a subprocess test with the stub. Red on the unmodified hooks: 4 of 16 emit-path tests fail with the leading line in the failure message (the file then had 16 tests), and 11 of 12 canary tests fail (n=12, this branch's canary test run against the `origin/main` 5c056309 hooks on 2026-11-03, `auto-route.py` passes). Narrow mutations, each turning a named test red: restoring `sys.stdout` before exit (`test_a_library_that_logs_to_stdout_at_exit_cannot_follow_the_decision`), dropping the logging init (`test_delegated_handoff_is_one_json_object`), dropping the rebind (the LiteLLM test). Rule: a hook's stdout is one JSON object or nothing, and a new hook script needs a payload in `PAYLOADS` of the canary test or that test fails.
