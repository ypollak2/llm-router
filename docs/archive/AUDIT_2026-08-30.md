# Audit — 2026-08-30 (post issues #59–#67)

Scope: whole repo at HEAD of `fix/issues-59-67`, with the nine uncommitted fixes in the
tree. Hunting for further instances of the same bug classes (A–F) the nine issues
established, not a generic review. `submissions/`, `scripts/routerarena/`, `experiments/`,
`data/`, `tests/bench/` excluded per instructions.

## 1. Verdict: **request_changes**

The nine fixes on this branch are sound as far as they go, but the audit surfaced a
sixth, larger instance of the exact pattern #62/#63 warned about: the entire
**enterprise profile is non-functional end to end** in the public package — config
load, server boot, RBAC enforcement, the audit trail, the CLI audit commands, and the
tool built specifically to catch this (`verify-enterprise`) all crash or silently
no-op, and `doctor`/`verify` never look at any of it. Separately, the #67 naming sweep
missed the CLI's own `--help` text (the highest-visibility surface in the whole
package) and most of `doctor`'s and `install`'s remediation hints. Neither defect is
touched by the current diff, so this branch should not ship as "the naming/enterprise
issues are handled."

## 3. Per-finding detail (high severity)

### F1 — RBAC strict/warn mode crashes every routed call
```
$ .venv/bin/python -c "
import os; os.environ['LLM_ROUTER_RBAC_MODE']='strict'
from llm_router.rbac_routing import check_route_prompt
class I: user_id='u1'; org_id='o1'; tenant_id=None
check_route_prompt(I())"
AttributeError: 'NoneType' object has no attribute 'ROUTE_PROMPT'
```
`check_route_prompt`'s own docstring says "This function does NOT raise" — it does, for
every mode except `off`, and nothing in `router.py:3491`/`4899` catches it. Because
`is_enterprise()` defaults RBAC to `strict` (G-001's "safety-on" design), the *intended
default posture of the enterprise profile* is what breaks it. Suggested fix direction:
either restore/ship a minimal `llm_router.enterprise.rbac` in the public distribution,
or make `rbac_routing.py` fail closed *cleanly* (raise the module's own
`PermissionDenied`-equivalent, not `None`-call errors) when the enterprise package is
absent, and have `check_route_prompt` genuinely never raise as documented.

### F2 — `LLM_ROUTER_PROFILE=enterprise` crashes MCP server boot
```
$ LLM_ROUTER_PROFILE=enterprise .venv/bin/llm-router
...
File ".../server.py", line 146, in <module>
    _slim = get_config().llm_router_slim
File ".../config.py", line 722, in get_config
    _config = RouterConfig()
pydantic_core._pydantic_core.ValidationError: 1 validation error for RouterConfig
llm_router_profile
  Input should be 'budget', 'balanced', 'premium', 'reasoning', 'quota_balanced' or 'subscription_local'
```
This is the *exact* env value `verify_enterprise.py::_check_profile_set_to_enterprise`
tells the operator to export, and the one `docs/PLAN_ISSUES_59-67.md` §4d assumes is a
routing-side no-op once #65 lands. It is not — `RouterConfig` (a completely separate
reader from `repo_config.py`'s `effective_profile()`, which #65 did fix) still binds
the raw legacy name with a strict enum, and it runs at **module import time**, before
any of the try/except scaffolding in `server.py` (`_critical_modules_or_die`,
`_startup_verify_or_die`) gets a chance to run. Suggested fix direction: rename this
field too (e.g. alias to `LLM_ROUTER_COST_PROFILE` matching the #65 direction) or make
it tolerant of unknown values with a fallback to `BALANCED`, consistent with how
`repo_config.py` now treats out-of-domain values as "not mine, ignore."

### F3 — `verify-enterprise` cannot be run and would crash if it could
Confirmed via direct call (`cmd_verify_enterprise(['--developer'])` →
`ModuleNotFoundError`) and via `grep -n enterprise src/llm_router/cli.py` (zero
matches). The one live caller, `server.py:465`'s `_startup_verify_or_die`, only fires
under `is_enterprise()` — which, per F2, never gets that far because `get_config()`
already crashed by then. Suggested fix direction: wire `verify-enterprise` into
`cli.py`'s dispatch (it's absent from `_KNOWN_SUBCOMMANDS` too, so even the #61
"did you mean" suggester can't point a typo at it) and wrap each enterprise-module
import in the same try/except pattern the other five files use, rather than a bare
`from llm_router.enterprise.x import y` inside the check functions.

## 5. Suggested new GitHub issues

**#68 — `LLM_ROUTER_RBAC_MODE=strict`/`warn` (and enterprise profile's default) crashes every routed call**
`rbac_routing.py:88`'s `_identity_has_route_prompt` calls `has_permission(identity, Permission.ROUTE_PROMPT)`, both of which are `None` because `llm_router.enterprise.rbac` isn't shipped; `router.py:3491` calls `check_route_prompt()` with no try/except. Repro: `LLM_ROUTER_RBAC_MODE=strict python -c "from llm_router.rbac_routing import check_route_prompt; check_route_prompt(None)"` → `AttributeError: 'NoneType' object has no attribute 'ROUTE_PROMPT'`, and the enterprise profile's own G-001 default ("strict") means turning on the officially safer mode takes the router down entirely.

**#69 — `LLM_ROUTER_PROFILE=enterprise` crashes MCP server startup at import time (RouterConfig, not repo_config)**
`config.py:264`'s `RouterConfig.llm_router_profile: RoutingProfile` is a second, unrelated reader of `LLM_ROUTER_PROFILE` that #65 did not touch (only `repo_config.py`'s `effective_profile()` was fixed); it validates against routing tiers and raises. Repro: `LLM_ROUTER_PROFILE=enterprise .venv/bin/llm-router` → `pydantic_core.ValidationError` at `server.py:146`, before any of `server.py`'s own startup-verification scaffolding runs — the documented way to enable the enterprise profile cannot boot the server.

**#70 — `verify-enterprise` is unreachable from the CLI and crashes if invoked directly**
`commands/verify_enterprise.py::cmd_verify_enterprise` has no caller anywhere in `cli.py` (`grep -n enterprise src/llm_router/cli.py` is empty) and isn't in `_KNOWN_SUBCOMMANDS`; its own checks (`_check_identity_db_reachable`, `_check_audit_db_reachable`, `_check_audit_chain_intact`) do unguarded `from llm_router.enterprise.* import ...` and crash with `ModuleNotFoundError` the moment they're called, including from `server.py`'s startup path. The one tool built to catch enterprise misconfiguration cannot itself run.

**#71 — `llm_router audit verify`/`export` crash with a raw TypeError instead of a clean error**
`commands/audit.py:23-28` sets `AuditLog = TamperDetected = None` on the same missing-module fallback; `_verify()` (line 40) calls `AuditLog()` unguarded. Repro: `llm-router audit verify` → `TypeError: 'NoneType' object is not callable`, not the documented exit-0/exit-1 contract.

**#72 — `llm-router --help` and most of `install`/`doctor`'s remediation text still say `llm_router` (underscore), not `llm-router`**
The #67 naming fix covered docs/skills/rules and "4 source lines" but missed `cli.py`'s module docstring (lines 4-51, 47 occurrences, printed verbatim by `--help`), `commands/install.py`'s `_INSTALL_HELP` and 8 other printed lines, and `commands/doctor.py`'s ~19 `fix=` remediation hints. Repro: `llm-router --help` prints `llm_router install`; `which llm_router` → not found. Every failing `doctor` check tells the user to run a command that doesn't exist.

**#73 — `llm-router setup`'s Gemini-subscription path writes the exact `LLM_ROUTER_PROFILE` value that now triggers the #65 deprecation warning**
`commands/setup.py:102` sets `new_keys["LLM_ROUTER_PROFILE"] = "quota_balanced"`. Repro: with that env set, `RepoConfig().effective_profile()` prints `[llm_router] DEPRECATED: LLM_ROUTER_PROFILE='quota_balanced' … Rename your env to LLM_ROUTER_COST_PROFILE (GH#65)` — every new user who runs the setup wizard and opts into Gemini subscription mode is immediately told to fix a value the wizard itself just wrote.
