P2.12 (P212-1): `llm-router install` now leaves an install receipt. Every full install writes `install_receipt.json` in the state dir (file mode 0600) with one row per host: claude-code, claw-code when wired, and every host `host_detect` finds. Each row says `wired`, `not_wired` (with the reason) or `error` (with the message), and for wired hosts the hook version read back from each installed hook file. A sha256 `digest` covers the package version and each host's status and hook versions, but not the timestamp, paths or how a host was wired, so two install paths that leave the same state give the same digest. The install prints one line, `receipt: <digest8> hosts=<wired>/<rows> version=<pkg>`. A host installer that raises, or a hook file missing after install, is now an `error` row and the install goes on to the other hosts, instead of aborting part way; a plain `llm-router install` then exits 1. New `llm-router install --auto`: the full install with no prompt and no daily-job question, for npm postinstall, the plugin and the MCP door to call; it exits 0 when every row is `wired` or `not_wired`, 1 when any row is `error`, and 2 when combined with `--host`, `--project`, `--check`, `--headless`, `--proxy-default` or `--authority`. Evidence: `tests/test_p212_receipt.py` (receipt contents, `--auto` against `run_full` on a twin HOME, a host-matrix cell for every host in `host_detect._HOSTS`, negative controls for a raising installer, a missing hook file and a wrong or missing receipt), plus a receipt assertion in `tests/test_p212_upgrade_from_15_4_0.py`.
