Add `llm-router setup-local [--yes]` (opt-in, never run by `install`): local routing on a 48 GB+ Mac. It refuses below 48 GB of RAM and when another Ollama's resident models plus this one would pass 75% of RAM, asks before the roughly 22 GB download (headless needs `--yes`), installs a supervised `com.llm_router.local-ollama` service on 127.0.0.1:11435, pulls and pins `qwen3.6:35b-a3b-coding` at the window the proxy requests (131072, from `LLM_ROUTER_WINDOW_STEP`; the model table says 32768), and writes `LLM_ROUTER_LOCAL_MODEL_URL`, `LLM_ROUTER_LOCAL_MODEL` and `LLM_ROUTER_WINDOW_STEP` to the state `.env` only when unset. After it, `install --proxy-default` gives the main proxy the local-agent arguments (`--serve local-agent --local-with-tiers --model ollama/... --ollama-url ... --trim none --keep-alive -1`); without it nothing changes. `doctor` gains a "Local routing" block (RAM, :11435, model resident, shim, settings.json base URL, `LLM_ROUTER_LOCAL_MODEL_URL`, a locally served row in the last 24 h; any "no" prints `local routing: NONE` and the fix). `uninstall` stops the service and removes only what setup-local wrote; the model stays unless `--purge-models`. Not measured here: the end-to-end run on a clean machine (parked), so no savings or quality claim is made. docs/proxy.md: the "flip script" reference (none exists in this repo) and the "nothing installs it" sentence are corrected.
