- Hand-over at a token limit (`hooks/status-bar.py`, hook version 14), OFF by default: with `LLM_ROUTER_HANDOVER_AT=<N>` (e.g. 150000) the UserPromptSubmit hook reads the real context size from the last main-chain assistant `usage` in the payload's `transcript_path` (input + cache_read + cache_creation input tokens; bounded 1 MiB tail read, only the usage dict is read) and, at or above N, adds one line of `additionalContext` telling Claude to write a hand-over file and tell the user to start a new session. At most once per 10 prompts per session (state in `handover_state.json` under `LLM_ROUTER_HOME`, mode 0600). Unset, 0 or invalid: nothing is read or written and the output is unchanged. A missing or malformed transcript fails open (no instruction). No saving figure is claimed: the design's $/day estimate is unmeasured here. Known limits (review 2026-11-26): right after `/compact` one stale reminder can fire (the last usage is pre-compact); a single assistant record larger than the 1 MiB tail read disables the check silently; the state file has no lock, so two sessions writing at once can lose one update (at most one extra or skipped reminder).
