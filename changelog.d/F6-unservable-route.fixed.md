The routing hook no longer names an `llm(task=...)` door that no provider on this machine can serve, and so enforcement no longer holds Bash/Edit for it. Before naming a task, auto-route (hook v61) asks the new `llm_router.task_availability` module. The module reads the cached resource map and the API-key names in the environment and `.env` files, with no network call and no config import. An unservable task falls back to the nearest servable task (research → query → analyze, analyze/generate → query, query → analyze, code → none). If no fallback can be served, the hook names no door and writes no pending state, and records the reason code in the debug log and the routing ledger. If availability is unknown (no map, or a corrupt or stale one), today's directive is kept. User prefixes (P2.7) still win.
