F107: `quota_history.jsonl` is bounded. It grew without limit (about 288 rows a day since P35-2 writes it from the default layout too) and `quota_rate` read the whole file on every refresher run. Now `statusline_tick.prune_history` keeps rows newer than 30 days (longest reader window is 14 days) and at most 20,000 rows, rewriting the file atomically under the writers' slot lock, at most once a day, only from the background refresher (never the synchronous tick); a failed prune is recorded as `F107-HISTORY-PRUNE`. `quota_rate` scans the file backward and stops at the first row older than its window. Retention is documented in `docs/RETENTION.md`. Read time: `quota_rate.median_pp_per_active_hour` on a synthetic 1-year history (n=105,120 rows, 14.9 MB, 15 runs, one machine, the default 14-day window): median 98.6 ms before, 7.6 ms after (same result: 0.6 pp/h over 336 active hours). The bound keeps the file near 30 days (about 8,640 rows).
