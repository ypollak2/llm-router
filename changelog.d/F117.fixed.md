F117: benchmark harness git and token-scan hardening (`scripts/p20_requal.py`, `scripts/p20_code_runner.py`). The token scan refuses on an unreadable (chmod 000) directory instead of skipping it, and the purge opens such directories through directory fds (O_NOFOLLOW, chmod by fd) so a symlink swapped in by a live agent cannot redirect the chmod. Harness git on an agent-touched repo reads bytes with a 128 MiB cap and a 120 s timeout and never reads the agent's `.git/config`: it runs against a harness-written git dir with no system/global config, scratch HOME, `GIT_NO_REPLACE_OBJECTS=1`, `--no-textconv --no-ext-diff` and overrides for fsmonitor, hooksPath, external diff, sshCommand, pager, gpg and related keys. **Behaviour change: every git failure (non-UTF-8 aside, which is scanned) such as a broken or deleted `.git`, a timeout or the output cap is a `Refuse` that aborts the whole run, where it used to be a `runner_error` row; this applies to the Pi arms too (through `empty_patch`).** The Claude-arm history scrub now scans the raw content of git objects the agent added (object ids snapshotted before the agent runs), instead of `git log -p --all` over the whole shared mirror, which exceeded the cap on every noncloud attempt; it also covers merges, tags, unreachable commits and replace refs. The Claude agent runs in its own process group and its process tree (descendants and env-tagged processes) is killed before the scan. `worktree remove` runs from the trusted clone. The interpreter probe no longer matches `pythonw` / `pythonista`. Evidence: `tests/test_p20_requal.py`, `tests/test_p20_code_runner.py`; limits in `docs/prereg/F104-AGENT-SCRATCH-HOME.md`.
