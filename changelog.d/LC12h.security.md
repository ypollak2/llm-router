LC-12h: every Ollama call to a loopback daemon bypasses HTTP proxies, and a prompt with a secret goes to a loopback local model or nowhere. (1) Proxy. LC-12g's per-call httpx client (`trust_env=False`, no redirects, closed after the call) now covers every `ollama/` and `ollama_chat/` call whose daemon (`OLLAMA_API_BASE`, else `http://localhost:11434`) is loopback, on every path, `providers.call_llm_stream_events` included (new `local_privacy.py`). LiteLLM's own model-info lookup (`POST /api/show` with the model name, the URL and `Authorization: Bearer $OLLAMA_API_KEY` when set, through the proxy) no longer runs for those models: the router asks the daemon once per process with `http.client` (no proxy, no key) and writes the answer into `litellm.model_cost` in LiteLLM's own shape, so LiteLLM treats the model as known. `config.probe_ollama` and the semantic cache's and semantic classifier's `/api/embeddings` use a urllib opener with no proxy handler and no redirects for a loopback base. Measured offline (fake proxy, fake Ollama and fake embedding host on 127.0.0.1, `HTTP_PROXY`/`ALL_PROXY` set, `NO_PROXY` unset, aiohttp and httpx transports): the fake proxy received no request of any kind on an ordinary local route, the secret door or the stream door, and the prompt reached only the fake Ollama (and, off the private paths, the fake embedding host). A non-loopback Ollama base is unchanged: LiteLLM's shared client, the user's proxy env and an explicit `NO_PROXY` apply. Not changed: model discovery, warm-up, the watchdog, `local_context_guard`'s window probe, the session-end context summary and the local classifier's eval path still use plain `urlopen`. (2) Secret door (D-28 A). `engine.Decision.local_only` existed but nothing in routing read it; the README's "Secrets never leave your machine" was not backed by code. Now `route_and_call` (the `llm_*` tools, the gateway), `route_and_stream` and the `llm_stream` tool scan the request's prompt, system prompt, caller context and messages with `engine.secret_names` (fails closed); on a hit the chain is cut, after every other chain step, to Ollama models on a loopback daemon that are not `-cloud` models, and an empty result raises `local_privacy.SecretLocalOnlyRefused` (a subclass of `engine.SecretLocalOnlyError`) before any model call. That dispatch gets the pass-only text job's privacy: the semantic cache is skipped (check and store), nothing is queued for the judge, there is no BUDGET emergency fallback, a non-local model or non-loopback daemon is refused in `providers` (`PrivateEndpointRefused`), and the PACK_OVERFLOW switch is refused when its target would leave the local set (a switch to another loopback local model is allowed). The LLM complexity classifier returns its fallback instead of sending such a prompt to a classifier model. User-visible: a prompt with a secret shape and no loopback local model is now refused instead of sent to a cloud model. Not covered: the Claude Code proxy (log only, D-28 A), agent delegation, session history the router injects after the scan, and secrets matching none of the shapes.
