SECDET: the secret door and the scrubber judge the token itself. A nearby `.env.example` / `.sample` / `.template` label or a `.example` host no longer exempts a real-looking key (that text is page- or site-controlled). A placeholder look exempts a token only when no long random body is left once the filler is cut out, so filler glued after or spliced into a real key (`xxxxxxxx`, `abcdefgh`, `-example`, `01234567`) no longer hides it. A key glued to preceding text (`mykeysk-ant-...`, `123AKIA...`, `键ghp_...`) and a percent-encoded key character (`sk%2Dant-...`) are now found by the door. Ordinary words that end in a key prefix are not keys: a glued generic `sk-` needs a mixed-case alphanumeric run with a digit (`task-` / `disk-` / `risk-` slugs, UUIDs, git SHAs and BEM classes are lower-case), a glued `AIza` / `gh[pousr]_` needs exactly the issued length, and `AKIA` is not read after an upper-case letter; an unglued key is matched at any length, so text glued after it never hides it. The scrubber redacts a percent-encoded secret span only (neighbouring `%26` / `%2F` stay as typed), finds a glued `ghp_` / `xox` token, and is linear on a long whitespace-free run (a stray `%` and the `db_url_credentials` scheme were both quadratic). The `exempted_by_label` counter is removed with the exemption. Residuals (double percent-encoding, HTML entities, base64, characters inside a token, `highp_` + exactly 36 mixed-case characters, a key glued on both sides) are listed in SECURITY.md.
