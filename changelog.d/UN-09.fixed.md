W1-2 (UN-09): the router's precision tier (a short prompt that asks for an exact answer, such as arithmetic, is fronted with `openai/gpt-4o-mini`) now asks the resource map and the user's stored rules before it adds that model. Before, it was added after the map filter ran, so a map that had disconnected `openai` (or a `ban openai` rule) was bypassed for those prompts. The new replay `tests/test_w12_ineligible_replay.py` (seed 20261029, run 2026-10-29, 1,026 generated requests over the router, gateway, hook, SDK and proxy doors, at least 100 evaluated routes per door, each door writing its decisions through its own stamp path into a throwaway `usage.db`, then the ineligible-route counter and an independent predicate read from the map rows) found this: 1 of 118 router requests and 1 of 118 gateway requests went to a disconnected `openai`, 0 on the hook, SDK and proxy doors. After the fix both checks read 0 on every door. Controls in the same file: planted ineligible decisions are all counted, and a build with the map filter disabled makes both checks go above 0 on every door. The live 7-day count (tag criterion 9) still waits for organic data and is not part of this change.
