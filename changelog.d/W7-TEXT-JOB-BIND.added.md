**Commit messages and PR bodies are written by the local model and bound into the command, not by Claude (BIND W7, owner decision D-360).** The model writes `git commit -m "${LLM_TEXT:?}"` or `gh pr create --title "<short>" --body "${LLM_TEXT:?}"`; the new PreToolUse[Bash] hook `llm_router-text-job-bind.py` builds the input from the real staged diff (or the branch's commits and diff), runs the router's own `llm_text_job` (local model only, the same checks), writes the checked text to a private file and rewrites the command to `-F <file>` / `--body-file <file>` through `updatedInput`, copying every other field. If the job is rejected, fails, times out or cannot run, or the command has a shape that cannot be bound (a `git add` earlier on the same line, `--amend`, a heredoc, ...), the command is denied with a short reason and Claude writes the text itself; a placeholder command is never allowed through unchanged. The placeholder is a shell variable with `:?`, so if the hook is not registered or is killed at its timeout the command does not run (Claude Code refuses a braced variable it cannot check, or the shell aborts it) and the placeholder is never committed or posted. The hook's stdout is exactly one JSON object (a private copy of file descriptor 1 carries it; the real script is run as a subprocess and parsed with `json.loads` in `tests/test_w7_hook_script.py`, with a control run that shows the canary does reach stdout without the guard). New: a text-free `text_job_binds.jsonl` ledger (one row per `git commit` / `gh pr create` command: bound, denied or hand-written) and `python -m llm_router.text_job_bind report`; the hook is instrumented for G1 and its model wait is the new `text_job` model phase. The rules text teaches the placeholder (rules version 12). Deploy: `llm-router install --force` once (registers the hook with timeout `130`; the plugin bundle carries the same entry). Design, limits and measurement: `docs/text-job-bind.md`.
