**Commit messages and PR bodies are written by the local model and bound into the command, not by Claude (BIND W7, owner decision D-360).** The model writes `git commit -m "${LLM_TEXT:?}"` or `gh pr create --title "<short>" --body "${LLM_TEXT:?}"`; the new PreToolUse[Bash] hook `llm_router-text-job-bind.py` builds the input from the real staged diff (or the branch's commits and diff), runs the router's own `llm_text_job` (local model only, the same checks), writes the checked text to a private file and rewrites the command to `-F <file>` / `--body-file <file>` through `updatedInput`, keeping every other field of the tool input and putting the generated subject into the Bash `description` so that the person approving sees what is committed. Every flag in the command survives the rewrite (`-am`, `-sm`, `-db`, `--draft`), and the hook proves it before emitting. Only the spelling `"${LLM_TEXT:?}"` is the placeholder (proved against `bash` and `zsh`); the variable written where the shell would not replace it (single quotes, a backslash, a here-document, without the `:?` guard) is denied, never passed through. A commit message is the model's subject plus, by default, a deterministic list of the changed files with their line counts (`LLM_ROUTER_TEXT_JOB_BODY=model|files|none`); mentions, closing keywords and a model-written `Test plan` are neutralised in what is published. If the job is rejected, fails, times out, finds the machine's one job slot busy, or cannot run, or the command has a shape that cannot be bound, the command is denied with a short reason and Claude writes the text itself; a placeholder command is never allowed through unchanged. The placeholder is a shell variable with `:?`, so if the hook is not registered or is killed at its timeout the command does not run and the placeholder is never committed or posted. The hook's own git reads cannot run a program named in the repository's configuration (file-system monitor, pager, external diff, textconv, filters), a diff past the byte cap still reports its true file count, and the hook loads `$LLM_ROUTER_HOME/.env` as the MCP server does. Jobs run one at a time per machine (a lock; a job that cannot get it in time is told "busy, write it yourself"), each model attempt is capped at the MCP door's per-attempt share, and the router import is booked as router time, not as the model's wait. The hook's stdout is exactly one JSON object (a private copy of file descriptor 1 carries it; the real script is run as a subprocess and parsed with `json.loads` in `tests/test_w7_hook_script.py`). New: a text-free `text_job_binds.jsonl` ledger and `python -m llm_router.text_job_bind report` (window and units, latency of every outcome, command-shape refusals apart from model failures, adoption from `--transcripts` or n/a with the reason); the hook is instrumented for G1 and its model wait is the new `text_job` model phase. The router's lane safety valve now judges jobs, not attempts: a job fails only if every try is rejected, and timeouts, busy, cooldown and a model that is not available do not count. The rules text teaches the placeholder (rules version 12) only when the hook is registered in `settings.json`, and `llm-router doctor` / `verify` report a mismatch. Deploy: `llm-router install --force` once (registers the hook with timeout `130` and `"if": "Bash(*LLM_TEXT*)"`, so Claude Code spawns it only for a placeholder command; the Claude plugin bundle carries the same entry, the Codex bundle does not). Because the filter hides hand-written commit and PR commands from the hook, the report needs `--transcripts` for an adoption figure. Design, limits and measurement: `docs/text-job-bind.md`.
