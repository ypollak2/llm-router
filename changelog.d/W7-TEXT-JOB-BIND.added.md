**Commit messages and PR bodies are written by the local model and bound into the command, not by Claude (BIND W7, owner decision D-360).** The model writes `git commit -m "${LLM_TEXT:?}"` or `gh pr create --title "<short>" --body "${LLM_TEXT:?}"`; the new PreToolUse[Bash] hook `llm_router-text-job-bind.py` builds the input from the real staged diff (or the branch's commits and diff), runs the router's own `llm_text_job` (local model only, the same checks), writes the checked text to a private file and rewrites the command to `-F <file>` / `--body-file <file>` through `updatedInput`, keeping every other field of the tool input and putting the generated subject into the Bash `description` so that the person approving sees what is committed. Every flag in the command survives the rewrite (`-am`, `-sm`, `-db`, `--draft`), and the hook proves it before emitting. Only the spelling `"${LLM_TEXT:?}"` is the placeholder (proved against `bash` and `zsh`); the variable written where the shell would not replace it (single quotes, a backslash, a here-document, without the `:?` guard) is denied, never passed through. A commit message is the model's subject plus, by default, a deterministic list of the changed files with their line counts (`LLM_ROUTER_TEXT_JOB_BODY=model|files|none`); mentions, closing keywords and a model-written `Test plan` are neutralised in what is published. If the job is rejected, fails, times out, finds the machine's one job slot busy, or cannot run, or the command has a shape that cannot be bound, the command is denied with a short reason and Claude writes the text itself; a placeholder command is never allowed through unchanged. The placeholder is a shell variable with `:?`, so if the hook is not registered or is killed at its timeout the command does not run and the placeholder is never committed or posted. The hook's own git reads cannot run a program named in the repository's configuration (file-system monitor, pager, external diff, textconv, filters), a diff past the byte cap still reports its true file count, and the hook loads `$LLM_ROUTER_HOME/.env` as the MCP server does. The flag and lane gate runs before the model libraries are imported, so a job the router would hand back anyway is denied in tens of milliseconds, and the wait for the job slot is booked as queue time, not router time. Only the user's own `$LLM_ROUTER_HOME/.env` is loaded, never the repository's. The generated text is cleaned before it is published (mentions, closing keywords, any test/testing/verification section, remote images and links, hostile file names in the files list). The adoption figure comes from transcripts of commands that really run `git commit` / `gh pr create`, never from the ledger. Jobs run one at a time per machine (a lock; a job that cannot get it in time is told "busy, write it yourself"), each model attempt is capped at the MCP door's per-attempt share, and the router import is booked as router time, not as the model's wait. The hook's stdout is exactly one JSON object (a private copy of file descriptor 1 carries it; the real script is run as a subprocess and parsed with `json.loads` in `tests/test_w7_hook_script.py`). New: a text-free `text_job_binds.jsonl` ledger and `python -m llm_router.text_job_bind report` (window and units, latency of every outcome, command-shape refusals apart from model failures, adoption from `--transcripts` or n/a with the reason); the hook is instrumented for G1 and its model wait is the new `text_job` model phase. The router's lane safety valve now judges jobs, not attempts: a job fails only if every try is rejected, and timeouts, busy, cooldown and a model that is not available do not count. The rules text teaches the placeholder (rules version 12) only when the hook is registered in `settings.json` AND a passed `commit_message` lane exists AND the off switch (`LLM_ROUTER_LOCAL_TEXT_JOBS` set to anything but 1/true/on/yes) is not set, with the pull-request part also needing a passed `pr_description` lane, and `llm-router doctor` / `verify` report a mismatch. Deploy: `llm-router install --force` once (registers the hook with timeout `130` and `"if": "Bash(*LLM_TEXT*)"`, so Claude Code spawns it only for a placeholder command; the Claude plugin bundle carries the same entry, the Codex bundle does not). Because the filter hides hand-written commit and PR commands from the hook, the report needs `--transcripts` for an adoption figure. Every git the hook starts gets a scrubbed environment (none of the owner's provider keys), filters of every name are neutralised, and the hook process runs from the owner's state directory so that the router's configuration is not read from the repository. Every URL that fetches or runs something, every markdown image marker and every embedding HTML tag is removed from the generated text by linear scans (best effort), and a stray placeholder on a line that may run git or gh (including `$G commit` and wrappers) is denied. The text-job-bind hook has its own G1 budget of 1,500 ms router-added (D-370); every other hook stays at 300 ms. Design, limits and measurement: `docs/text-job-bind.md`.
