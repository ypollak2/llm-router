P1.8 task 6, readers: the router chain (`_build_and_filter_chain`), the hook chain (`hooks/chain_builder.build_chain`), the proxy chain (`policy_chain`) and the dynamic routing table now read `~/.llm-router/resource_map.json` when a usable map exists. Semantics: the map always FILTERS (resources whose status is not connected are dropped); it REORDERS by `effective_priority` only when the map's routing policy expresses an order (any policy other than `balanced`, e.g. `local-first`, `cost`). Under the default `balanced` policy the ranks are only row order, so today's cheap-first order is kept. `chain_builder._apply_subscription_local` follows the same rule when a map is present. The MCP server's dynamic table (previously build-once) and the proxy chain cache are rebuilt when the map is rewritten, and also when it is deleted or older than 6 h (back to the no-map result); the proxy chain cache is cleared on each change. With no map file, a stale, unreadable or other-schema one, or a filter that would empty the chain, every chain is exactly what it was. Readers never build the map. Doors (`llm-router map [--json]`, `llm_router_status(view="map")`) were already on main with the map core (#402).
