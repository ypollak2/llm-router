P3.6-a and P3.6-b (classifier learning and self-protection, R-CLS-5, R-CLS-7, R-RTE-7). **Learning store and update gate:** `examples.jsonl` now also takes human-validated redos (the `r` key on the receipt band) and "always local" rules, next to the forced-prefix rows it already held; a row holds the prompt hash, a 0/1 label and, only when the kNN index is on and has an artifact, the embedding the index would hold anyway, never prompt text. New `llm-router learn [--dry-run] [--replay PATH] [--json]` folds the rows that carry an embedding into the L3 kNN index, but only after re-scoring the candidate index on a held-out replay set (`LLM_ROUTER_LEARNING_REPLAY`, at least `LLM_ROUTER_LEARNING_MIN_REPLAY` rows, default 100): an update that worsens exact-match or under-route by more than 2 points, or that has no usable replay set, is rejected and the live index is left untouched (the previous one is kept as `complexity_knn.json.prev` after an accepted update). Under D-121 there is no L2 few-shot path, so the examples feed the L3 kNN only. **Classifier health:** `llm-router status` (and `kpi` when there is data) shows the 7-day shadow agreement with n against the prior 28 days, and a PSI line for the rules' tier mix. A drop of 5 points or more at n >= 100 in both windows switches on conservative mode: the proxy tier policy looks the tier up one complexity level higher, and one notice line is printed; it never fires below n = 100, and `LLM_ROUTER_CLASSIFIER_CONSERVATIVE=off` removes the bias. Agreement is shadow-vs-rules agreement, not ground-truth accuracy; with no shadow rows it prints "not measured (n=0)". Retention: `docs/RETENTION.md`.
