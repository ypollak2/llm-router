LC-12e: Ollama cloud models (a `-cloud` tag or the `cloud` tag, e.g. `gpt-oss:120b-cloud`, `<name>:cloud`, case-insensitive) are excluded from local routing; the local Ollama daemon serves them, but the prompt leaves the machine. `llm-router local-check` refuses to run on one ("cloud-hosted Ollama model; local-check measures local models only"), so it writes no PASS and switches no lane on. The eligibility guards (`prefer_passed`, `passed_model_leads`, `passed_lane_available`) never treat one as routable, even when a `local_routing.json` written before this fix says passed. The D-277 local-only cut in `route_and_call` also refuses one and releases the budget reservation, so `llm_text_job` returns `fallback` ("do this job yourself") with no model call. Detection uses one predicate, `resolver.inventory.is_ollama_cloud_model`, which the inventory's existing cloud marker also uses. A name that only contains "cloud" (`cloudy-model:7b`) is not a cloud tag. The local-only path now fails closed when its cut-site check raises (no leaked reservation). The hand-back text says when the eligibility step itself failed. Fail-closed refusals have their own durable counter, `text_job_fail_closed`, which `llm-router doctor` shows; the fail-open counter `CHZ-FO-ROUTER-ELIGIBILITY-FILTER` now counts only true fail-open cases. Test fix: `_pending_spend` comparisons in `tests/test_lc12c.py` use `pytest.approx` (a float flake on py3.11 CI). Evidence: `tests/test_lc12e.py`.
