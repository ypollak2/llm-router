The local routing verdict now runs in the hooks (`llm_router/door_verdict.py`), not only in the proxy shadow. `auto-route.py` logs one text-free row per routed prompt and `agent-route.py` one per routed Agent spawn in `door_verdicts.jsonl` (verdict, door, residency, latency, outcome, `tool_use_id`), written by a detached worker so no prompt waits for it. With `LLM_ROUTER_LOCAL_CLASSIFIER=on` the tier verdict is a difficulty signal that picks the door: opus at p_max >= 0.6 keeps the work on Claude (hint quieted, or no Codex attempt for the spawn); haiku at >= 0.7 goes local first where a local lane can do the job (a passed quality batch, or a commit-message / PR-description prompt with the local text-job switch on; `preferred_door(verdict, kind=..., local_lane=...)` is the seam for a sub-agent fallback); sonnet, or haiku with no lane, goes to Codex first (the prompt hint gains `llm(prompt="codex: ...")` when Codex is usable; spawns keep the existing Codex gates). Thresholds: `LLM_ROUTER_DOOR_OPUS_MIN_CONF`, `..._HAIKU_MIN_CONF`, `..._SONNET_MIN_CONF`. Of the 7-day proxy verdicts (n=1,755) 4.1% reach the Claude door at its threshold, 6.8% are local-eligible before the lane test, 53.4% reach the Codex door. A verdict opens no door the existing gates keep shut. A breaker opens only after two failures in a row. `scripts/door_verdict_report.py` reads the ledger; `scripts/door_verdict_check.py` and `scripts/door_verdict_hook_cost.py` are real checks capped at 30 and 20 model calls.
