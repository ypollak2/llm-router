PLAN v16 P1.1 door 7: the gateway's completion endpoints (`/v1/chat/completions`, `/v1/responses`, `/v1/messages`, `/api/chat`, `/api/generate`) no longer flatten the message list into one `role: text` prompt. The trailing user turn is sent verbatim as the request and the turns before it go to `route_and_call(messages=..., context_door="gateway")`, which builds the context with `build_pack(door="gateway")` for each provider attempt. As on the SDK door, history is sent only when `session_store.allows_session_content(provider)` allows it (`LLM_ROUTER_SESSION_CONTEXT=local` keeps it off API providers, `off` sends none), a conversation over the pack window keeps its last 7 messages, and a pack error records `CHZ-FO-ROUTER-GATEWAY-PACK` and sends the request alone. Gateway calls no longer read this process's own session into the prompt. A request without a trailing user turn (an assistant prefill, a system-only request) is still sent flattened, with no history. `route_payload` accepts an optional `messages` list (a non-list is a 400); without it, the native `/route` is unchanged.
