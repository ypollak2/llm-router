PLAN v16 P1.1 door 7: the gateway's completion endpoints (`/v1/chat/completions`, `/v1/responses`, `/v1/messages`, `/api/chat`, `/api/generate`) no longer flatten the message list into one `role: text` prompt. The trailing user turn is sent verbatim as the request and the turns before it go to `route_and_call(messages=..., context_door="gateway")`, which builds the context with `build_pack(door="gateway")` for each provider attempt. As on the SDK door, history is sent only when `session_store.allows_session_content(provider)` allows it (`LLM_ROUTER_SESSION_CONTEXT=local` keeps it off API providers, `off` sends none), a cloud attempt keeps the whole conversation up to 0.8 x a 32,768-token gateway window (`_GATEWAY_NON_LOCAL_WINDOW`, owner decision; the SDK and MCP doors stay at 8,192) and otherwise its last 7 messages, and a pack error records `CHZ-FO-ROUTER-GATEWAY-PACK` and sends the request alone. Gateway calls no longer read this process's own session into the prompt. A request without a trailing user turn (an assistant prefill, a system-only request) is still sent flattened, with no history. `route_payload` accepts an optional `messages` list (a non-list is a 400); without it, the native `/route` is unchanged. New `tests/test_context_pack_doors.py` checks that `context_pack.DOORS` is exactly the seven doors, that each has a `build_pack` call site and its own door test file, and that an unknown door is rejected.
