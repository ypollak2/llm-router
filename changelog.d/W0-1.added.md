W0-1: every routing decision row carries `layer`, `confidence`, `reason` and `inventory_sig`, so "routes to an ineligible model" and the `llm-router why` layer become countable. Evidence: 2,717 `routing_decisions` rows, `layer` and `inventory_sig` empty on all of them (independent audit, 2026-10-25). New `decision_stamp` module; writers stamped: `router.route_and_call` (MCP tools and the gateway), the failed-call row in `cost` (layer NULL), `hooks.savings_logger.log_direct_to_db` (hook, agent-route, SDK) and the proxy ledger (`cls_layer`, `cls_confidence`, `cls_reason`, `inventory_sig`, stamped at write time). `layer` is a closed set (`decision_stamp.LAYERS`: the ledger layers `prefix`/`L1`/`cache`/`L3`/`L2`/`fallback` plus `heuristic`, `llm`, `cached`, `override`, `unhinted`, `rules`, `knn`); a door or method name (`agent-route`, a fast-path name) is stored as NULL. `confidence` is the classifier's own number and NULL when it has none (override, fallback, unhinted, prefix, 0.0): never fabricated. `inventory_sig` is sha256[:12] of the resource map's per-resource chain id, status, effective priority, capabilities (tools, vision) and context window, plus the policy (not quota or timestamps). The first time a signature is computed its inventory is stored in the new `inventory_snapshots` table of `usage.db` (never deleted, like `routing_decisions`, which has no TTL; see `docs/RETENTION.md`) and `decision_stamp.resolve_inventory(sig)` returns it, so a row stays checkable after the map changes. The signature is cached per process keyed on `map_reader.token()`: a map rewrite changes it on the next call; a warm call is one `stat`. NULL when there is no usable map. Rows written before this change stay NULL. Not stamped: the lineage store's separate `routing_decisions` table and `model_tracking.jsonl`.
