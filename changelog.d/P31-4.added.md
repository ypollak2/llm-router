Judge queue hygiene and spend caps (P3.1-4). `judge_queue.jsonl` is the only judge file with text: an entry whose prompt or answer matches a `secret_scrubber` pattern is skipped whole (failopen `CHZ-FO-JUDGE-QUEUE-SECRET-SKIP`, no text in the record), the rest passes `shadow_text.scrub` and `persist_redact`, is capped at 8000 characters each, and the file is created and rewritten mode 0600. Entries are deleted at claim; unclaimed entries older than `min(LLM_ROUTER_PERSIST_TTL_DAYS, LLM_ROUTER_JUDGE_QUEUE_MAX_AGE_DAYS (3))` are purged at drain and at the enqueue size check. `_enforce_queue_cap` now does one `stat` per enqueue and re-reads the queue only below 64 KB or when an append crosses a 256 KB stride, instead of reading the whole queue on every hook-path enqueue. New `judge_ledger.jsonl` (no text; capped at 5000 rows): `ts, door, answering_model, judge_model, judge_kind, tokens, cost_usd (None = unknown, 0 only for a measured local call), outcome`. The Haiku judge, still off unless `LLM_ROUTER_JUDGE_HAIKU_FALLBACK` is set, now also stops with a recorded outcome at `LLM_ROUTER_JUDGE_HAIKU_MAX_CALLS` (20/day, `cap_calls`), `LLM_ROUTER_JUDGE_HAIKU_MAX_TOKENS` (400000/day, `cap_tokens`), and whenever the quota reading is stale or unknown, session >= 80% or weekly >= 85% (`quota_skip`); the flag is re-checked at call time (`privacy_off`). Judge calls run with `ANTHROPIC_BASE_URL` removed so they never loop through the proxy. `llm-router judge status` and `llm-router kpi --judge` show today's calls and tokens against the caps. Fixes F93: a cloud answerer whose last path segment equals an installed local model's name (`openai/foo` with local `foo`) is no longer classed local, so it can never reach the Haiku path. Evidence: `tests/test_p31_judge_hygiene.py`.
