Delegated Codex runs (`agent-route.py`, including its Phase-2 CLI path) now choose their sandbox from the session's directory, the hook payload's `cwd` (owner decision D-357, ruled "write in repo"). A session inside a git work tree gets `--sandbox workspace-write` with the network off (`sandbox_workspace_write.network_access=false`), and the work tree's top level is the only writable root and Codex's working directory. A session rooted at the home directory, outside any repository, or in a repository that sits at or above the home directory gets `--sandbox read-only` (network off as well), and a reply that reports blocked work is not delivered, so Claude's sub-agent does the task. A session rooted at `/` is not delegated (`codex_unsafe_cwd`). Before, every delegated run was read-only and most answers reported blocked work. The router chain and the MCP tools still pass no sandbox flag, and `danger-full-access` cannot be requested through `run_codex`. The Phase-2 path now has the blocked-answer gate the NS3 path had. `delegated` and `codex_blocked` ledger rows carry the `sandbox` the run had. `northstar` counts a `codex_blocked` row as a discarded attempt.
