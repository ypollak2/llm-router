PLAN v16 P1.1 door 7 follow-up: the gateway keeps tool calls in the history it hands `build_pack(door="gateway")`. Responses API `function_call` / `function_call_output` (and custom/local-shell tool) items and OpenAI `tool` results used to be dropped or rewritten before the pack saw them; they now pass through, and the pack renders them as `[tool_use: name] args` / `[tool_result] output` like every other door. A trailing turn that carries only tool output (Anthropic `tool_result` blocks, an OpenAI `tool` message, a Responses `*_output` item), the normal next step of an agent client, is now the request instead of being flattened away with the history; text beside a tool result stays in the request. The router's T4-M1 redaction and budget estimate for a caller's history now cover every string in a message (tool-call arguments, `tool_use` inputs, nested `tool_result` text, Responses tool output), not only `content` and block `text`; ids and image payloads are neither redacted nor counted. New `context_pack.render_message`.
