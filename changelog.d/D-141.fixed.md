MCP tool errors are readable: an unexpected exception from any llm-router MCP tool now reaches the client as `llm-router error: <ExceptionType>: <message>` (plus the models tried, when known) instead of the bare `Error executing tool <name>`, while cancellation still propagates. `llm()`, `llm_route` and the task aliases run under an overall deadline (`LLM_ROUTER_MCP_DEADLINE_S`, default 90 s, 0 = off); inside it each provider attempt through LiteLLM is capped at half the deadline (45 s by default, previously the 120 s request timeout), so a hung local model falls through to the next candidate, and an expired deadline returns `llm-router error: deadline <N>s exceeded; tried: <models>; ...` instead of a call the client has already abandoned.
