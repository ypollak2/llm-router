`scripts/synthetic_replay.py` network guard: the guard was installed as `sitecustomize.py` in the scratch venv. On Debian and Ubuntu Pythons, the distribution's own `/usr/lib/python3.X/sitecustomize.py` comes earlier on `sys.path` and shadows it, so no replay child was ever guarded and every run reported 0 network violations. The guard now loads from a `.pth` import line (`00_replay_netguard.pth` → `_replay_netguard_baked`), which a system `sitecustomize` cannot shadow. `tests/test_synthetic_replay.py::test_a_door_pointed_off_the_stub_fails_the_run` and `::test_guard_is_baked_into_the_child_interpreter` pass again in such environments. Also adds a mixed-window family to the D-101 registry-window tests, so a max-instead-of-min mutation of the family rule is caught.
