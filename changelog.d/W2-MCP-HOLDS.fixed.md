**Routing holds no longer invite throwaway `llm_*` calls, and no longer fire on prompts that are not requests (BIND W2).** The `Routing directive BLOCKED` text used to say that calling any `llm_*` tool, even a trivial one, clears the lock, and the model did: `Reply OK` probes sent only to release the hold. A hold is now released only by a routing door whose input carries the owner's request (`llm`, `llm_route`, `llm_act`, `llm_edit`, ...). A trivial or unrelated call, or a status view, still runs but leaves the hold in place and is logged as a probe. The free valves (the second block of one tool in a turn, three in two minutes, a fourth violation) and the `claude:` prefix still release without a model call. In `smart` mode (the default) a prompt of ten words or fewer, or the "This session is being continued" summary Claude Code injects after a compaction, writes no hold; `hard` and `strict` keep every hold. `enforce-route.py` now writes its decision to a stdout reserved for one JSON object, so a stray library print can no longer void a hold or a local interception. A tool that crashes in an MCP server older than its package now says to reconnect with `/mcp`, and while Ollama is saturated a call that is still waiting on local models gives up after 20 s instead of the full 90 s deadline. New: a text-free `hold_events.jsonl` ledger and a `blocked_holds` counter in `llm-router doctor`; `python -m llm_router.hold_ledger` prints BLOCKED, holds and probes per 100 prompts. Deploy: `llm-router install --force` (hooks auto-route 79 and enforce-route 25), then reconnect with `/mcp`. Evidence and limits: `docs/bugs/BIND-TOLL-1.md`, `BIND-HOLD-1.md`, `BIND-STDOUT-1.md`, `BIND-MCP-STALE-1.md`, `BIND-MCP-BUSY-1.md` and the section "When a prompt holds a tool" in `docs/proxy.md`.
