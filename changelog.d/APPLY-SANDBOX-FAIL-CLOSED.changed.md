The `llm_apply` check sandbox now fails closed: `LLM_ROUTER_APPLY_SANDBOX` defaults to `require` (was `auto`, which ran the check unsandboxed when no backend was usable); `auto` and `off` remain as explicit opt-outs, and a refused check says why and names the opt-out. The sandbox refuses a ROOT that is HOME, the account's home, or any ancestor of either, compared by file identity so case variants on case-insensitive APFS and symlinks are caught; any ROOT with fewer than 3 path components (`/`, `/usr`, `/etc`, `/Users`, `/home`, `/opt`), macOS `/private` system paths (`/private/etc`, `/private/var`, `/private/tmp` and the `/etc`, `/var`, `/tmp` aliases), and anything under `/System` (including the `/System/Volumes/Data` volume that contains the home folders). `ROOT/.git` is read-only inside the sandbox on macOS and Linux, so a check can no longer plant git hooks or config. Source: independent security review 2026-11-25 (findings M1-M4 plus three review rounds on the fix).
