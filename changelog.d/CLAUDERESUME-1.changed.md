Claude CLI offload (subscription): repeated offloads in one llm-router session now continue ONE `claude -p --resume` session instead of folding the whole session buffer into a fresh flat prompt each time, so earlier turns can be read from the prompt cache. The first offload in a (llm-router session, scope root, cwd, model) runs as before with `--output-format json` and records the CLI `session_id`; later offloads send only the new request (plus an explicit `caller_context`) and skip re-injecting OKF/repo context the session already holds. Session-accumulator entries that other providers added since the session's last turn are not re-sent on a resumed turn (the accumulator has no cheap "since" ordering; the idle cap bounds the staleness).
- Session identity: only `call_identity.call_session_id()` (a Claude Code MCP call). The `CLAUDE_SESSION_ID` / `CLAUDE_CODE_SESSION_ID` env vars and the machine-wide pointer file are not used, because they are process-wide and would share one CLI session across callers. With no session id, or with a caller-supplied `conversation`, every call is fresh. Two conversations can still share a key in the cases `call_identity` documents: several Claude Code sessions on one SSE server process share its env id, and after `/clear` on a long-lived server the id is stale. Sub-agents of one conversation in the same cwd and model share a session by design.
- Fresh (old-behaviour) call when: no stored id; the resume errors, returns `is_error`, or comes back with no parseable session id; the CLI answers with a different non-empty session id (that key then stays un-resumed for an hour); the session has been idle over `llm_router_claude_offload_resume_ttl_s` (default 3300 s, under the 1-hour cache the CLI writes) or holds `llm_router_claude_offload_resume_max_ctx_tokens` (default 150000) or more; or another offload on the same key is still in flight (it runs fresh instead of waiting).
- Switch: `llm_router_claude_offload_resume` / `LLM_ROUTER_CLAUDE_OFFLOAD_RESUME`. Off by default; enable with `LLM_ROUTER_CLAUDE_OFFLOAD_RESUME=1`. Off keeps text mode and the flat prompt exactly as before, and none of the changes below to tokens or `api_equivalent_cost_usd` apply.
- Token semantics changed for these rows: `input_tokens` is now the CLI's UNCACHED input only, with `cache_creation_input_tokens` / `cache_read_input_tokens` set separately, instead of the `len(prompt)//4` estimate. This reaches the usage table: `cost.log_usage` computes `potential_cost_usd` and `saved_usd` from these fields, so offload rows now price the cache components. Cache writes from the CLI are priced at the 1-hour cache-write rate (`LLMResponse.cache_write_1h`), not the 5-minute write rate used for other calls. Other callers and the global price table are unchanged. After a discarded resume that was redone fresh, the token fields cover the final call only.
- `api_equivalent_cost_usd` on the response is the CLI's `total_cost_usd` as a per-call delta (it is cumulative under `--resume`), plus a discarded call's cost when known; `None` when the CLI did not report it or a discarded call's cost is unknown. `cost_usd` stays 0.0 because the subscription is flat-rate; `api_equivalent_cost_usd` is not written to the usage table or the savings report.
- For calls run in JSON mode, `on_event` progress lines arrive after the call finishes (the CLI prints one JSON document), not while it runs. With the switch off, text mode is unchanged.
