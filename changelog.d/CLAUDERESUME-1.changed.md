Claude CLI offload (subscription): repeated offloads in one llm-router session now continue ONE `claude -p --resume` session instead of folding the whole session buffer into a fresh flat prompt each time, so earlier turns can be read from the prompt cache. The first offload in a (llm-router session, scope root, cwd, model) runs as before with `--output-format json` and records the CLI `session_id`; later offloads send only the new request and skip re-injecting OKF/repo context the session already holds. A fresh call (the old behaviour) is used when there is no stored id, the resume errors or returns `is_error`, the CLI answers with a different session id (resume then stays off for an hour), the session has been idle over `llm_router_claude_offload_resume_ttl_s` (default 3300 s, under the 1-hour cache the CLI writes), or it holds `llm_router_claude_offload_resume_max_ctx_tokens` (default 150000) or more. The session is keyed on `call_identity.call_session_id()` or `CLAUDE_SESSION_ID` / `CLAUDE_CODE_SESSION_ID`, never the machine-wide pointer file; with none of those, or with a caller-supplied `conversation`, every call is fresh. Switch: `llm_router_claude_offload_resume` / `LLM_ROUTER_CLAUDE_OFFLOAD_RESUME` (default on; `false` restores text mode and the flat prompt). The response now carries the CLI's real per-call tokens (`input_tokens` = uncached input, plus `cache_creation_input_tokens` / `cache_read_input_tokens`) instead of the `len(prompt)//4` estimate, and `api_equivalent_cost_usd`: the CLI's `total_cost_usd` as a per-call delta (it is cumulative under `--resume`), `None` when the CLI did not report it. `cost_usd` stays 0.0 because the subscription is flat-rate; `api_equivalent_cost_usd` is not written to the usage table or the savings report. Calls with the switch off, or whose output was not the JSON document, keep the old estimates.
