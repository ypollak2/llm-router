LC-5 (local-check scoring, library only; no CLI command yet): new `llm_router.local_check.score` (per-item success = programmatic grader ok AND judge pass, pooled k/n over commit_message + pr_description with per-lane counts and Wilson intervals; verdict PASS at k >= kmin(n) (56 of 70, 112 of 140), powered FAIL when the Wilson upper bound is < 0.80, otherwise INCONCLUSIVE; a lane below 0.70 is excluded from the PASS; early stop when failures make kmin unreachable gives `not_passed` with partial counts, not a powered fail; `--no-judge` can only give FAIL or a probe, never PASS; a grader rule behind >= 40% of failures is reported; gates G0 integrity, G1 serves (timeouts, errors and empties counted once per row), G3a grader self-test, G3b plants and G5 completeness make a run INVALID and record nothing), `local_check.attempts` (per model/digest/bank/settings anti-retry log: draw 1 first, draw 2 only on a rerun, verdict on the cumulative union of 140, a third same-configuration run is refused, 24 h cooldown unless forced) and `local_check.session` (one check end to end, all collaborators injected, writes through `record_local_check` with bank, digest, runtime, judge, run id, scope, settings hash and attempts). `record_local_check` now accepts verdict `NOT_PASSED` and a lane `status` (`not_passed`, `lane_guard`), stored on a `failed` lane. Evidence: `tests/test_lc5_scoring.py` (fakes only, real bank; the stored Q37 qwen run re-scored with the ported scorer gives PASS 60/70, 32/35 commit_message and 28/35 pr_description).
