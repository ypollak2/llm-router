P3.1-7: judge figures ride on `ledger_view` windows. `LedgerWindow` gains `judge_n`, `judge_mean` (None at n=0), `judge_self_judge` and `judge_not_informative` (n<50), read from `judge_view.judge_summary` for the same bounds as the window (additive; `to_json`/`from_json` stay at v2 and an older cache without the fields loads as unknown, printing `n/a`, never 0), plus `LedgerWindow.judge_line()` and a `judge` entry in `figures()`. `window_summary(..., judge=True)` is opt-in (default False): the judge read parses all of `judge_results.jsonl` (O(file)), so the synchronous Stop path (`dashboard_data.summary`), the refreshers, gain and the savings report never pay it; only the kpi judge section and the session-end child's ledger cache opt in. Measured on a synthetic 50,000-row judge_results.jsonl (7.0 MB, 30 d spread, scratch home, median of 5, macOS): `window_summary("24h")` 72 ms with the judge read vs 0.1 ms without (the scratch usage.db was empty, so that is a floor, not a typical ledger cost); `dashboard_data.summary("today")` 0.1 ms, no judge read. The kpi judge section parses the file once (was twice). The kpi judge section's headline figures now read `ledger_view.judge_figures`; the statusline snapshot and the Stop line keep reading the `judge_summary.json` cache (the same `judge_view` function; their equality with the ledger window is tested). Evidence: `tests/test_p34a_six_surfaces.py` (hand-counted judge n/mean/self-judge over seeded `judge_results.jsonl` for today, 24h, 7d and 14d, equal across the ledger window, kpi, the statusline snapshot's cache and the Stop's cached line).
