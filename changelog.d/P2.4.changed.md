P2.4: the capability filter is on by default and excludes, never reorders. A chain entry known to lack tools (the request carries tools, or the prompt needs them), vision (images present) or window (system prompt + newest turn + tool schemas over 90% of the model's window; history is not counted, packs adapt to each window) is removed at the router/MCP/gateway door (the last transform before the empty-chain check, and on the emergency BUDGET chain), the hook and SDK door (`execute_chain`) and the proxy door (`choose_model(needs=)`). An unknown capability never excludes, and an explicit pin is not exempt (the error names the capability). `LLM_ROUTER_CAPABILITY_ROUTING=0` turns the filter off. Behaviour changes: the default flip also makes the hook's `needs_claude_tools` use the 8-bit capability vector instead of the legacy boolean, so the hook falls through to Claude more often (symbol, repo-search, git and command prompts now count), and `routing_decisions.capabilities_json` is written on every decision. The gateway now refuses image parts with HTTP 400 on every completion route instead of silently dropping them (same class as the `tools` refusal). `docs/empty-chain-behaviour.md` documents what each caller does when every map-known provider is disconnected, and `tests/test_p24_empty_chain_table.py` pins the table to the behaviour. Evidence: `tests/test_p24_capability_hard.py` and `tests/test_p24_empty_chain_table.py`.
