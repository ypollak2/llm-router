LC-12b (follow-ups to #702): `LLM_ROUTER_LOCAL_TEXT_JOBS` now fails closed. Only unset or empty means unset; `1`/`true`/`on`/`yes` are on, `0`/`false`/`off`/`no` are off (case-insensitive, whitespace-stripped), and any other value (`disable`, `nope`) is off, so a typo can no longer hand `llm_text_job` to a pass-routed local model. With the flag unset, `llm_text_job` also refuses (`fallback`, no model called) unless the router's chain actually leads with the passed Ollama model (`PassedModelNotInChain`), so a cloud model that the user never opted into cannot serve the call; after the local model the fallback chain is the same as under `=1`. The tool is listed only for enabled lanes of Ollama models; a manual `enable` for a non-Ollama model prints the D-274 note, and `local-check` now says the `llm_text_job` tool appears after the next MCP restart or reconnect. Evidence: `tests/test_lc12b.py`.
