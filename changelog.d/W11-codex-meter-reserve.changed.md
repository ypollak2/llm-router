The Codex Plus meter is reserved for sub-agent delegation (owner decision D-373). Every Codex caller except agent-route (the `llm_codex` MCP tool, the router chain, Codex-served text jobs, the evaluator, the calibrator, the session broker, and any caller that names nothing) now refuses once the WEEKLY meter reaches 60% (`LLM_ROUTER_CODEX_RESERVE_PCT`, `off` disables). The meter is read from the newest `payload.rate_limits` in Codex's own rollout files (`src/llm_router/codex_meter.py`, read-only, newest by event time, never older than 30 minutes); with no fresh reading the router's own counters decide (100/day agent-route budget, 5 h window) and if those cannot be read the call is refused, never opened. A refusal is a failed call (`reason_code=meter_reserved`, nothing started), is written to `codex_meter.jsonl`, and its wording cannot be parsed as a usage-limit report, so it never benches Codex. Not covered: the CLS and backend-bench harnesses start `codex` with their own argv (`scripts/cls_send_lib.py`, `scripts/bench_backend_quality.py`).
